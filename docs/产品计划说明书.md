## 一、项目概述

许多人在知乎收藏过大量高质量回答和文章，却很少真正回看。收藏解决了“以后可能需要”，没有解决“现在如何读懂”。当用户终于打开一篇内容时，还会遇到两个障碍：作者默认读者已经知道的领域背景，以及正文中被省略的推导过程。

知识蒸馏站连接用户已有的知乎收藏夹，把收藏内容组织成一条可继续的学习路径：先帮助用户判断哪篇值得投入时间，再围绕收藏兴趣发现相关内容，最后把文章拆成适合逐步理解的小段，通过解释、划选追问、自测和复习帮助用户完成一次学习。

产品的核心是**让每个不懂的地方都有继续理解的入口**。AI 补充必要背景、解释具体片段，用户保留阅读、判断和推进的主动权。阅读位置贯穿收藏卡和学习记录，让一次没有读完的学习可以继续。文字解释、选区解释与追问均归当前用户独享；原文更新后，系统通过 Git 内容版本继承未修改段落，使同一用户可以继续使用自己已经生成的解释。

## 二、目标用户与需求

### 2.1 目标用户

- 有知乎收藏习惯，但收藏量远大于阅读量的学生和职场新人；
- 想系统学习某个主题，却不知道应先读哪一篇的人；
- 能读懂字面意思，但容易在专业背景、概念关系或逻辑跳步处掉队的人；
- 主要利用碎片时间学习，需要自动保存进度和快速恢复上下文的人。

### 2.2 核心问题

1. **收藏没有形成行动。** 原生收藏夹适合保存和查找，不负责安排学习节奏。
2. **内容价值难以快速判断。** 面对大量标题，用户缺少选择阅读对象的参考。
3. **理解过程容易中断。** 用户遇到陌生概念时需要离开原文查资料，返回后还要重新寻找阅读位置。
4. **看完缺少反馈。** 阅读结束后，用户还需要机会检查自己能否区分概念、回忆关键内容。

### 2.3 典型使用场景

以一名准备学习机器学习的学生为例。他收藏了一篇讨论“过拟合”的知乎回答，却在“偏差与方差”处读不下去。进入知识蒸馏站后，他可以先阅读当前段的解释，再选中不懂的术语请求补充；如果补充解释中的另一个概念仍然陌生，就在那层文字上继续划选、深入理解，再逐层返回原文。读完后，他可以通过自测检查概念辨析；中途退出，下次从收藏卡即可接着读。

## 三、产品方案

知识蒸馏站围绕“看见—发现—学会”形成三层体验。

### 3.1 看见：把收藏夹变成学习入口

用户通过知乎 OAuth 登录后，系统读取其收藏夹及收藏内容，并以卡片形式呈现标题、作者、收藏时间及可用配图。卡片提供三项独立的阅读参考，用户可以查看计算依据并选择排序方式。

| 页面指标 | 当前计算依据 | 适合帮助用户判断什么 |
|---|---|---|
| 认可度 | 收藏、赞同、评论数量，经对数缩放后加权 | 内容获得的社区反馈 |
| 信息量 | 摘要长度、分点结构、引用链接等信号 | 内容是否包含较丰富、结构化的信息 |
| 准确性 | 作者信息、签名、内容类型及摘要中的引用链接 | 来源信息是否充分、是否存在可追溯线索 |

其中“准确性”目前是公开信号的估计值，未实现事实核验；三项分数都不能替代读者对原文及其证据的判断。

用户可以切换收藏夹、排序和分页。已经保存全文的内容可直接进入精读，并自动恢复到上次读到的段落；尚未保存的内容会引导用户回到知乎原文，通过保存书签把完整正文送入学习空间，完成后自动跳回并开始阅读。

### 3.2 发现：从已有兴趣出发继续探索

系统从用户收藏中提取兴趣线索，调用知乎搜索寻找同主题的公共内容，排除已经收藏或保存的条目，并使用与收藏卡一致的方式展示。推荐的作用是补充发现，而不是替用户修改或替换原有收藏。

### 3.3 学会：围绕原文逐段精读

文章进入学习空间后，AI 按语义边界切分为若干短段。界面一次聚焦当前段：左侧保留原文，右侧提供解释，补足必要背景并指出关键逻辑连接。

当用户仍有疑问时，可以在原文或解释中划选具体片段，再点击提问按钮请求解释。文字解释、选区解释、主动输入的问题及其后续回答都按用户身份保存，只对本人可见。解释中仍有不懂的部分时，用户可以继续划选，进入下一层解释，再逐层返回。

每次保存全文都会形成 Git 内容版本。段落文字未变化时，新版本继承原有段落标识，同一用户可继续复用自己在旧版本中生成的解释，并能看到解释最初对应的内容版本；被修改或删除的段落不会在新版本中展示旧解释。用户可主动重新生成解释，系统将创建新的解释修订并按本次实际模型用量扣除积分。

界面以当前文本和解释为中心。输入问题后，回答作为当下阅读的补充临时显示，用户可关闭它继续阅读；产品不另设提问历史列表。临时显示指界面的呈现方式，相关问题仍会作为学习节点保存。

用户通过“我懂了”推进到下一段，系统自动记录阅读位置。完成全文后，用户可以选择：

- 进入自测，模型以五道题为目标，生成考查知识记忆或概念辨析的判断题、选择题；
- 直接复习，回顾文章重点与论证脉络；
- 在自测后针对最近一轮答错或跳过的内容进行个性化复习；
- 返回收藏夹继续选择下一篇内容。

首次进入产品时，用户会通过六个场景了解“收藏—保存—精读—追问—自测—复习”的完整流程。界面支持桌面与移动端导航、窄屏阅读、深色主题和移动端保存书签指引。

## 四、核心使用流程

1. 用户使用知乎账号登录知识蒸馏站。
2. 选择一个收藏夹，浏览并筛选想学习的回答或文章。
3. 首次使用时按引导安装保存书签。若全文尚未保存，从站内打开知乎原文页并点击“保存这篇文章”书签；保存完成后自动回到学习界面。
4. 系统按语义切分全文，用户逐段阅读原文和自己的解释。
5. 用户在不理解的位置划选文字，点击提问按钮查看进一步解释；需要时可在解释中继续划选。
6. 对需要调用模型的操作，服务端先按输入估算检查当期积分，执行后再按返回的 `total_tokens` 结算实际用量；缓存命中不重复扣费。
7. 用户确认理解后进入下一段，进度自动保存。
8. 读完后进入自测或复习；下次从收藏卡或学习记录返回时，自动接上原来的段落。
9. 原文形成新版本后，系统只在未修改段落上继承本人已有解释；修改或删除的内容按新版本重新学习。

这一流程把选文、阅读、理解卡点和读后练习串联起来。阅读进度表示读到的位置，“我懂了”表示用户主动推进，二者都不等同于系统认定用户已经掌握知识。

## 五、AI 能力设计

### 5.1 语义分段

模型负责判断自然段之间的语义关系，后端根据自然段边界计算字符切点，将内容组织成适合逐段阅读的长度。原文按位置切分，保留内容与顺序，减少模型直接改写原文带来的偏差。

### 5.2 上下文解释与递归追问

每段解释参考文章标题、全文主旨和当前段落，重点补充必要背景与推导中的连接。用户的选区被记录为所在文本中的位置，后续解释与选区及其父节点关联。所有文字解释与追问节点归生成它的用户独享。这样，读者不仅能提出问题，也能看清这个问题出现在原文或哪一层解释里。

### 5.3 高级解释

高级会员可主动请求高级解释。该操作通过知乎 DSH 能力补充搜索或工具调用获得的上下文，与普通解释分别缓存和计费；最终结果仍作为该用户的解释修订保存。高级解释是会员功能，不会自动替换用户已有的普通解释。

### 5.4 自测与复习

读完后，模型根据文章内容生成判断题或选择题，未作答题目的正确答案不随题面下发，作答判定在服务端完成。答错时，系统针对用户实际选择给出讲解。复习内容根据进入路径变化：直接复习回顾文章，自测后复习聚焦最近一轮答错或跳过的题目。

自测用于帮助用户发现需要回看的内容，题目和讲解仍属于 AI 生成结果，不能视为学习成效认证。

### 5.5 积分额度与模型计费

- 积分直接表示可调用的模型 Token 数量，首版固定为 **1 Token = 1 积分**；
- 普通用户每个额度周期获得 **50,000 积分**，高级会员每个周期获得 **500,000 积分**；
- 每日北京时间 **04:00** 开始新周期，避免在自然日零点鼓励用户熬夜透支次日额度；
- 单次操作先预留额度，再以 DeepSeek 返回的 `usage.total_tokens` 结算，多预留部分立即返还；
- 跨越 04:00 的在途请求仍结算到发起时所在周期，防止重复获得额度；
- 本人查看已生成内容、命中本人缓存以及恢复阅读均不扣积分；主动重新生成会产生新的解释修订并重新计费；
- 高级会员价格暂定为 **19.9 元/月**。当前没有支付商户账号，购买与独立充值入口暂不开放，系统不虚构支付成功或积分到账。

账户页展示会员状态、本周期总额度、已用积分、剩余积分及下次重置时间。服务端是额度判断的唯一可信来源，前端数值仅用于展示。

### 5.6 AI 使用边界

- 原文始终保留，AI 不以改写稿替代作者内容；
- 三项指标是阅读参考，不宣称自动判断事实真伪；
- 所有文字解释、选区解释与追问按用户隔离；内容版本之间只复用同一用户、同一继承段落的节点；
- AI 生成失败、接口限额或数据为空时，界面提供真实错误和重试提示。

## 六、整体技术方案

### 6.1 架构

```text
浏览器端（原生 HTML / CSS / JavaScript）
        │
        ▼
FastAPI 服务
  ├─ 知乎 OAuth 与用户会话
  ├─ 收藏夹全量分页与智能推荐
  ├─ 全文保存、图片清洗与索引
  ├─ Git 内容版本、段落继承与当前版本读取
  ├─ 分段、个人解释、追问、自测与复习
  ├─ 积分预留、实际 Token 结算、周期重置与会员权限
  └─ 个人解释缓存 + 公共功能缓存
        │
        ├────────► 知乎开放能力
        ├────────► DeepSeek Flash 模型服务
        ├────────► 知乎 DSH 高级解释能力
        ├────────► CloudBase PostgreSQL REST / RPC 持久层
        └────────► 腾讯云对象存储挂载（/data/content.git）
```

### 6.2 技术选型

- **前端：**原生 HTML、CSS、JavaScript，无构建步骤，降低部署复杂度；KaTeX 资源本地化，稳定渲染公式。
- **后端：**Python + FastAPI，负责鉴权、业务接口、文本处理和 AI 编排。
- **模型：**DeepSeek OpenAI 兼容接口，模型名固定为 `deepseek-flash`，用于语义分段、解释、提问、自测和复习；高级解释接入知乎 DSH SDK。
- **内容版本：**使用裸 Git 仓库保存原文版本和段落继承关系。生产环境将腾讯云对象存储挂载到 `/data`，仓库位于 `/data/content.git`，不启用会额外收费的 CFS 文件存储。
- **业务数据：**CloudBase PostgreSQL 保存分段索引、用户私有解释树、解释修订、阅读事件、自测、作答、会员状态和积分流水。涉及额度与版本一致性的写操作通过数据库 RPC 原子完成。
- **部署：**CloudBase 云托管常驻容器，使用 HTTPS 域名完成知乎 OAuth 回调。
- **运行支撑：**公共功能继续使用共享缓存；文字解释与追问使用用户级缓存。启动时检查 Git 对象与引用读写能力，检查失败时停止版本写入；服务凭证通过环境变量配置。

## 七、使用的知乎开放能力

| 知乎能力 | 产品用途 | 用户价值 |
|---|---|---|
| OAuth 登录与授权用户信息 | 建立用户会话，展示登录身份 | 无需另建账号体系，直接连接个人收藏 |
| 收藏夹列表与收藏夹内容 | 全量读取用户主动保存的文章和回答 | 学习内容来自用户真实兴趣，而不是平台预设课程 |
| 知乎搜索 | 根据收藏兴趣寻找同主题公共内容，并补充作者信息 | 从个人积累自然延伸到知乎社区中的相关知识 |

知乎内容提供真实的问题、经验和讨论语境，AI 负责围绕这些材料提供理解支持。当前精读解释基于用户保存的文章和阅读上下文生成，知乎搜索主要用于推荐与作者信息补充。

完整正文由用户在已打开的知乎原文页主动点击保存书签送入，收藏接口提供的摘要用于选文和展示。页面保留原文入口，用户可以返回知乎核对作者观点和上下文。

## 八、与知乎社区生态的契合

知乎社区积累了大量有解释深度的回答和文章，也沉淀了用户长期形成的收藏行为。知识蒸馏站不另造一套内容库，而是从用户已经认可并收藏的知乎内容出发，降低优质内容被遗忘的概率。

产品希望从三个方面促进内容被持续阅读：

1. **让旧内容重新被阅读。** 学习记录和自动续读把一次性收藏转化为持续访问。
2. **让相关内容获得新的发现入口。** 智能推荐把用户的收藏兴趣连接到更多知乎公共内容。
3. **尊重作者原文与来源。** 精读界面保留标题、作者和原文链接，解释围绕原文展开，不把 AI 生成内容冒充作者观点。

## 九、对社区用户的实际价值

- **对学习者：**减少挑选成本，在具体卡点获得解释，并通过进度、自测和复习完成学习闭环。
- **对创作者：**保留作者身份与原文入口，让曾经被收藏的长内容获得再次阅读的机会。
- **对知乎社区：**将收藏、搜索和内容阅读连接起来，为增加内容复访与深入阅读提供产品入口。
- **对多人使用场景：**原文、分段、摘要、题库和搜索等公共能力可以共享；每个人的文字解释与追问保持私有，避免不同学习路径相互干扰。

这些是产品预期带来的价值，当前尚未通过用户对照实验量化验证。

## 十、创新点

1. **从个人收藏出发。** 学习对象不是通用课程，而是用户已经表达过兴趣的知乎内容。
2. **由读者决定学习节奏。** AI 用于分段、背景补充和卡点解释，用户自行选择深入的位置，并决定何时进入下一段。
3. **解释可以递归深入。** 用户能在解释中继续选择不懂之处，使学习深度由真实困惑决定。
4. **私有解释跨版本延续。** Git 保存原文版本，稳定段落标识让未修改内容继续关联本人解释；修改和删除的段落自然退出新版本。
5. **按实际用量结算。** 系统以供应商返回的 Token 总量扣除积分，预留与结算原子完成，缓存命中不重复收费。
6. **阅读位置贯穿产品。** 收藏卡、学习记录和阅读页共享同一进度，用户回来即可继续。
7. **把读后练习接入阅读。** 自测提供回看线索，复习根据答题结果聚焦薄弱点。

## 十一、实现状态与验证

当前版本已实现以下功能：

- 知乎 OAuth 登录、收藏夹切换与收藏内容全量分页；
- 三项阅读参考、排序、推荐与卡片状态；
- 书签保存全文、保存后自动跳回学习页；
- AI 分段、逐段解释、划选解释、递归追问与公式渲染；
- 用户私有解释树、解释修订，以及 Git 内容版本间对未修改段落的继承；
- `deepseek-flash` 模型调用、基于 `usage.total_tokens` 的积分预留与实际结算；
- 普通用户每日 50,000 积分、高级会员每日 500,000 积分，以及北京时间 04:00 周期切换；
- 账户页额度展示、会员权限检查及高级解释入口；
- 学习记录、自动续读、读后自测和两种复习路径；
- CloudBase 持久化、缓存、空数据与失败提示；
- 六场景产品介绍、深色主题、桌面与移动端导航、窄屏阅读、移动端书签说明，以及按教程版本记忆展示状态的新手引导。

截至 2026 年 9 月 15 日，正式分支最新功能提交为 `4a4fef4`。后端与前端相关代码通过 **166 项自动化测试**，另有 **8 项依赖外部环境的测试跳过**；前端脚本语法、页面元素标识和样式结构检查通过。上述验证覆盖本地功能契约，不能代替真实 CloudBase 数据库和公网环境验收。

计费、私有解释和内容版本所需的数据库迁移已经写入项目，但尚未在真实 CloudBase PostgreSQL 执行。为防止数据库结构不完整时误扣额度，计费开关默认关闭，必须在迁移和预发布验收通过后开启。CloudBase 构建镜像已经成功；对象存储挂载端点仍需改为带 `https://` 的完整地址后重新部署。当前没有支付商户账号，因此 19.9 元会员购买和独立充值均未上线。

全文学习需要用户安装并使用保存书签；首次分段和首次生成解释需要等待模型响应。自测与复习当前最多向模型提供原文前 20,000 字，超长文章的覆盖范围因此有限。移动端已完成响应式交互，但仍需在主流手机浏览器上做真实设备验收。

## 十二、后续计划

后续工作以当前阅读体验的稳定性与验证为先，沿已确定的方向推进：

| 阶段 | 工作重点 | 验收关注点 |
|---|---|---|
| 数据库验收 | 在 CloudBase PostgreSQL 执行迁移，验证额度、私有节点和内容版本 RPC | 并发请求不超扣；失败可回滚；用户之间不能读取解释；跨 04:00 请求只结算一次 |
| 部署验收 | 修正对象存储端点后重新部署，完整体验登录、收藏、保存、精读、自测、复习和续读 | Git 仓库在重启后保留；评委可独立完成操作；失败时可理解并恢复 |
| 多端验证 | 在桌面与主流手机浏览器完成真实设备回归 | 导航、选区、解释层级、书签说明、额度展示和安全区布局可用 |
| 会员上线 | 取得国内支付商户能力后接入 19.9 元/月会员购买 | 支付回调验签、重复通知幂等、退款与会员到期规则明确；未付款不授予权益 |
| 使用验证 | 邀请目标用户试用，观察从收藏进入学习和中断后继续阅读的过程 | 用户能否理解积分与保存书签；是否能在具体卡点获得帮助；回访能否顺利继续 |

效果评价将区分“完成阅读流程”和“理解了内容”：前者关注流程完成及再次阅读，后者需要结合用户的概念解释、练习反馈和后续回忆情况。产品会依据这些证据继续调整解释与练习方式。
