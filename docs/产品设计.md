# 知识蒸馏站 · 产品设计

> 版本：v0.1（2026-09-13 初稿，待团队确认）
> 用途：指导开发 + 产品说明计划书的底稿

---

## 一、问题定义

### 目标用户
在校学生与毕业三年内的职场新人（正与赛事人群重合）：有收藏习惯、有学习焦虑、时间碎片化。

### 核心痛点
**收藏 ≠ 学会。** 知乎的收藏夹是「知识的坟场」：
- 收藏的瞬间以为自己会回来看，实际上再也没打开过；
- 即使打开，面对一堆标题也不知道从哪篇开始、哪篇值得花时间；
- 挑出一篇开始读，又遇到两类卡壳：
  - **不了解的领域**：文章默认读者有背景共识，可新手没有，第一段就看不懂；
  - **跳跃的逻辑**：作者省略了推导步骤，读者在中间「掉队」，越读越懵，最后放弃。

### 现有方案为什么不够
- 知乎原生收藏夹：只有列表和时间排序，不解决「学什么、学不学得会」；
- 通用 AI 问答（RAG 类）：从零开始问答，不接个人收藏资产，学完也不沉淀回收藏夹；
- 学习类 App：内容不是用户真正想学的那篇（用户收藏什么才是真实意图信号）。

## 二、产品定位

**一句话**：连接你的知乎收藏夹，把它从坟场变成学习进度表——先告诉你哪篇值得学，再逐层教到懂。

**差异化（评审创新度视角）**：
1. **从个人收藏出发**：用户收藏行为本身就是最强的兴趣信号，比任何推荐算法都准；
2. **三指标量化「值得学的程度」**：认可度（社区认同）× 信息量（内容厚度）× 准确性（可靠程度），把模糊的「这文章好不好」变成可比较的数字；
3. **主动补背景 + 拆逻辑**：不是总结原文，而是补上「作者默认你懂但你不懂」的共识，拆开「作者跳过的推导」。

## 三、核心概念：三指标

| 指标 | 回答的问题 | 数据来源 | 计算口径（v1） |
|---|---|---|---|
| 认可度 | 社区觉得这篇好吗？ | 收藏接口的 LikeCount / CommentCount / FavoriteCount | 三计数对数缩放后加权（收藏权重最高，收藏是「值得再看」的信号） |
| 信息量 | 这篇内容多厚？ | Title / Summary 长度与结构 | 摘要长度、段落结构、引用密度（链接/代码块/公式）、术语密度启发式 |
| 准确性 | 这篇可信吗？ | 搜索接口 AuthorBadge（认证标）+ 直答交叉验证 | v1：认证标分级；v2：直答抽查关键结论一致性 |

**呈现**：每条收藏卡片显示三个指标条 + 一个综合「学习价值」分；排序支持按综合分 / 收藏时间。

**关键产品决策**：指标不是最终目的，**帮用户挑出「一直想学却没弄懂」的那篇才是**。因此卡片上还要有：
- 收藏时间（多久没碰了——愧疚感转化为行动力）
- 「我一直没弄懂」手动标记按钮（用户的自我认知是最强信号）

## 四、用户旅程（三层能力）

### 第一层：看见（今天必须完成）
1. 用户用知乎账号登录（OAuth）；
2. 系统读取收藏夹（favlists → favlist_contents 全量分页），带进度反馈；
3. 每条收藏展示：标题 + 三指标 + 收藏时间 + 作者；
4. 用户浏览、排序、标记「想学没弄懂」；
5. 选出目标 → 进入学习会话。

### 第二层：替换（9/14）
1. 对选中的内容，用知乎全站搜索找同类；
2. 按三指标对比，推荐「更高分 / 更好懂」的替代或补充内容；
3. 用户可选择换成更好懂的那篇开始学。

### 第三层：学会（今天出基础版，9/14 完善）
学习会话 = 针对一篇文章的三步：
1. **补共识**：用直答/搜索生成「读这篇前你该知道的背景」，只讲领域共识，不重复原文；
2. **拆逻辑**：把文章推导链拆成步骤，标出跳跃点（作者省略了什么、为什么可以省略）；
3. **补材料**：扫描文中论文 / GitHub 链接，抓取摘要并解释「这篇材料的哪部分对应文章的哪个结论」。

## 五、技术设计概要

```
浏览器 ──> app/server.mjs（Node 零依赖）
              ├─ /api/oauth/*        官方模板：登录、回调、会话
              ├─ /api/collections    收藏夹全量拉取（favlists + favlist_contents 分页）
              ├─ /api/analyze        三指标计算（服务端，纯函数）
              ├─ /api/session/*      学习会话（直答调用、链接抓取）
              └─ 内存缓存（TTL 10min）——额度 100 次/天/能力组，必须缓存
```

**额度预算**（每天 100 次/能力组）：
- 用户数据组：收藏全量拉取 1 次/用户/10 分钟（缓存命中不消耗）；
- 搜索组：第二层每篇 1 次；直答组：学习会话每步 1 次。
- 开发期用本地样本 JSON 调试，不反复打接口。

## 六、MVP 范围（严防蔓延）

| 优先级 | 功能 | 时间 |
|---|---|---|
| P0 | OAuth 登录 + 收藏夹全量读取 + 三指标卡片 + 标记目标 | 9/13 |
| P0 | 学习会话「补共识 + 拆逻辑」基础版 | 9/13 晚–9/14 |
| P1 | 第二层同类推荐 | 9/14 |
| P1 | 公网部署 + 回调配置 + 真实登录验收 | 9/14 前 |
| P2 | 第三层论文/GitHub 深挖 | 9/14 视进度 |
| P2 | 数据可视化打磨、动效、移动端适配 | 9/14 晚 |

**砍掉清单**（明确不做）：注册体系、多收藏夹管理、社交功能、导出、消息通知。

## 七、评审视角自查

| 权重 | 我们的回答 |
|---|---|
| AI 场景价值 40% | 真实痛点（收藏坟场）+ 明确人群（学生/新人）+ 从数据到行动到学会的完整闭环，不是玩具 |
| 创新度 25% | 三指标量化学习价值 + 补共识/拆逻辑的教学式 AI 用法（区别于总结式 AI） |
| 完成度 25% | P0 全绿 + 公网可跑 + 错误降级（空收藏夹/额度耗尽/接口失败都有真实提示） |
| 设计感 10% | 卡片式三指标 + 时间线的「愧疚感」设计 + 克制的动效 |

## 八、待确认问题

1. 学习会话的输出形态：对话式（可追问）还是报告式（一次性给全）？——倾向先报告式（快、稳定），再放开追问；
2. 三指标权重：人工拍定还是可让用户调节？——MVP 拍定，作为后续亮点；
3. 「你没弄懂的可能性」预测：要不要做？——MVP 用用户手动标记，不预测；
4. 产品名称/域名/标语：需要定，影响项目广场展示和计划书。
