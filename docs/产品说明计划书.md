# 知识蒸馏站 · 产品说明计划书

> 连接你的知乎收藏夹，把只进不出的收藏夹变成一条走得完的学习进度表——先告诉你哪篇值得学，再陪你逐段读到懂。

# 一、核心创作思路与目标用户

## 1.1 你是否有过这样的场景

深夜刷知乎，刷到一篇好回答，写得是真明白。你一边点头一边想："这么好的内容，必须码住，周末专门抽个时间好好读一遍。"手指很诚实地点下收藏，心里还有一点小小的踏实感——好像这篇的知识，已经随着收藏进了脑子。

然后呢？然后就没有然后了。那个"周末"永远在下一个周末。隔几个月大扫除式地点开收藏夹，两百多条收藏安安静静躺在那里，时间最近的停在上个月，时间最久的已经开始吃灰，你一篇都没有再打开过。最扎心的是那句流传很广的自嘲：**收藏从未停止，学习从未开始。**

偶尔咬咬牙真点开一篇，读了三段，撞上一个看不懂的概念，卡住，默默退出——顺手又收藏了一篇"讲这个概念的"。循环完美闭环，知识并没有进来。

把这串熟悉的日常拆开看，它断在三个环节：面对几百个标题，**挑不出**哪篇真值得花时间；真读了，缺的共识没人补、断掉的推导没人接，**读不进**；至于读没读完、懂没懂，更从来没有人管，**没下文**。收藏夹就这样变成一个只进不出的地方——知识蒸馏站要接住的，正是这三件事。

## 1.2 我们的思路：不做总结 AI，做精读仪器

面对"读不进去"，很多工具的答案是"帮你总结"——把一篇好文章压成三句话。但阅读研究早已提示：无约束地把答案递给学习者，撤走 AI 之后成绩反而更低——Bastani 等人 2025 年发表在 PNAS 的实验里，这一组比从未用过 AI 的对照组成绩还低 17%，而带保护设计的组没有这种负效应；反过来，让学习者自己解释、自己推进的"自我解释"式学习，效应显著为正——Bisra 等人 2018 年的元分析给出 g 值 0.55，短会话的效果还要更好。

所以知识蒸馏站的 AI 有一个明确的立场：**不替用户读**。AI 负责三件事——**筛选**，量化一篇内容的阅读价值；**补齐**，解释你缺的领域共识、指出逻辑断点；**检测**，出题检验你是否真的读懂。而最关键的那件事，由用户亲自完成：**自己把文章读完、想通**。节奏由你的"我懂了"推进，推导由你亲手想通，AI 始终只站在辅助的位置上。

## 1.3 目标用户

**在校学生与毕业三年内的职场新人**——有收藏习惯、有学习焦虑、时间碎片化。他们不缺内容，缺的是把内容真正变成自己东西的那条路。

# 二、用户如何完成核心体验

产品的核心旅程是一条完整的线：**筛选 → 发现 → 精读 → 沉淀**，全程有学习智能体陪读。

## 2.1 筛选：三指标把收藏夹变成可排序的清单

用知乎账号登录后，收藏夹全量加载为内容卡片。每篇内容有三个独立量化的指标：

| 指标 | 回答的问题 | 依据 |
|---|---|---|
| 认可度 | 社区觉得它好吗？ | 赞同 / 评论 / 收藏三计数对数加权 |
| 信息量 | 它有干货吗？ | 标题与摘要的长度、结构、引用密度 |
| 准确性 | 它可信吗？ | 作者认证信息等公开信号 |

按任一单项或综合分排序，悬停可见每一分的计算依据——**不黑箱**。

## 2.2 发现：收藏夹空着，也能开始

收藏夹没东西的用户不会被挡在门外：输入一个想搞懂的关键词，就能搜到知乎站内的相关内容，点开原文收藏或保存，直接进入学习。已有收藏的用户，系统会根据收藏画像推荐同主题的优质内容，作为收藏之外的补充——**只做发现，不做替换**：收藏是用户自己的选择。

## 2.3 精读：逐段读到懂

点开一篇已保存全文的内容，进入精读会话。**AI 分段**把全文切成约 600 字、语义边界优先的段落，一次只读一段，降低认知负荷。**两栏递进**的界面里，左栏是原文，右栏是这一段的解释——解释里默认补上"文章默认读者懂、新手却没有"的领域共识；读解释时还有疑问，可以继续追问，层层下钻。**划选即解释**：选中任意文字即可生成解释，标记为实线下划线、全站共享——你卡住的地方，别人大概率也卡住，第一个人的提问变成所有人的注释。打字提问则是**私有**的：虚线标记、仅自己可见，锚定选区或当前段落。底部"我懂了 →"是唯一的推进方式，读完一段是一段，"上一段"随时最小回溯。**AI 不生成全文摘要**，读的主体始终是用户。

## 2.4 学习智能体：会提问，更会找答案

精读页里住着一个学习智能体。它不是普通的聊天窗口——回答你的问题时，它会自主调用外部工具。问刚刚发生的事、问随时间变化的知识，它会现场检索全网和知乎站内的资料，带着来源回答，而不是凭训练时的旧记忆硬答；术语对照、公式演算、结构梳理这些内置技能，按问题的需要自动启用——问公式它就算，问概念它就查证，问结构它就拆解。它还知道自己正在陪你读哪一段、你之前划选过什么、问过什么，回答永远接得上你此刻的困惑。工具的使用过程对你透明：查了什么、引用了哪里，一目了然。

## 2.5 沉淀：读完之后，学过留痕

读完不等于结束。**自测**会出 5 道题，模型自行决定考知识记忆还是概念辨析、用判断还是选择，答错时它会针对你选的那个选项讲清楚错在哪，而不是复读一遍正确答案；**复习**按你的作答情况重点讲薄弱处，"跳过"视为不懂，不放过任何含糊；**学习记录**自动保存每篇读到的段落，侧边栏随时带你回到上次停留的位置。

## 2.6 会员：把深度学习再往前推一步

产品的完整闭环——三指标筛选、逐段精读、共享解释、自测复习——对所有用户免费。**会员**解锁学习智能体的进阶能力：更高的智能体对话额度，支撑论文季、求职季的高强度学习；联网搜索与技能调用的更充分使用；学习报告、跨篇知识串联这类新能力，也先向会员开放。

会员的存在让产品可以长期运转下去：免费用户贡献共享解释，会员支撑算力——**学习这件事，不该由广告来买单**。

# 三、整体技术方案

```
浏览器：原生前端，无构建
   │
FastAPI 服务端：Python
   ├─ 知乎开放平台 API ── 登录 / 收藏数据 / 知乎搜索 / 全网搜索
   ├─ DeepSeek 大模型 ── 分段 / 解释 / 智能体问答 / 出题 / 复习
   └─ 云开发 PostgreSQL ── 全文 / 分段计划 / 解释树 / 埋点，持久化
```

三个值得一提的工程决策：**分段不靠模型"报坐标"**——让模型直接输出字符切点会出现幻觉偏移，我们改为模型只给语义分组、服务端精确计算字符切点，左栏展示的永远是原文本身，逐字不差，位置锚定才可靠。**两级缓存是产品的生命线**——解释、题目、搜索结果都按内容键全站共享，一个用户生成的解释，后来者直接命中；这是在开放平台每日额度约束下，把"一个人用的工具"做成"一群人用的产品"的关键设计，使用的人越多，站内的共享注释越厚，边际成本越低。**智能体工具调用有边界**——联网搜索与技能调用由服务端编排：模型决定要不要查、查什么，检索与执行在服务端完成并把来源带回给用户，回答可溯源，过程不失控。

持久化在云端数据库：全文、解释树、学习进度重启不丢；共享解释人人可见，私有提问仅本人可见。

# 四、使用的知乎开放能力

| 能力 | 用途 |
|---|---|
| OAuth 登录 + 授权用户基础信息 | 账号连接与身份展示 |
| 用户数据 API：收藏夹列表与内容全量分页 | 产品数据底座：把收藏夹变成三指标清单 |
| 知乎搜索 | 发现层：关键词搜索与画像推荐；获取作者认证信息 |
| 全网搜索 | 学习智能体的外部工具：提问时现场检索资料、补足上下文 |
| 额度查询 | 用量透明化与预算管理 |

**边界声明**：本产品不抓取、不搬运知乎内容。全文的获取来自用户在知乎页面上主动触发的书签保存行为；所有内容卡片均跳转知乎原文。

# 五、与知乎社区生态的契合点

知识蒸馏站是一个**不离站的深度阅读器**：产品里的每一次点击最终都回到知乎原文，卡片跳原文、收藏发生在知乎、保存由用户在知乎页面主动完成，我们是知乎内容的"加深层"，不是替代品。共享划选解释直接长在知乎内容上，**给优质回答补一层"新手注释"**：一个用户在难懂处生成的解释，全站后来者直接受用，优质内容越难啃的部分注释越厚——这是社区知识的二次沉淀。搜索与推荐全部指向知乎站内内容，**让"收藏"重新有下文**：用户被引导回知乎发现更多优质创作者，收藏这个动作从"存了就忘"变成"学习进度表的第一行"，用户会更愿意收藏、更常回来。同时，两级共享缓存让开放平台接口的每一次调用产生最大的社区价值，用量透明可查，**在额度约束内与平台共生**。

# 六、对社区用户的实际价值

对读者，价值落在三件具体的事上：**挑一篇的时间**，从"翻二十分钟收藏夹"变成"按综合分排一下"；**读一篇的完成率**，由 600 字一段、自己控速、随时续读兜住，长文不再是"收藏了就等于读了"；**读懂的确定性**，读不懂的地方有解释、有智能体带着工具找答案、有自测检验，"我懂了"不再是自我感觉。而每一位用户的划选与提问，都在为后来的读者铺路——**公共注释越用越厚**。

对内容创作者，同样有价值：你的回答被更多人**真正读完、读懂**，而不是躺在收藏夹里积灰。
