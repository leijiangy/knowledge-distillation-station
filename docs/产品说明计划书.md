# 知识蒸馏站 · 产品说明计划书

> 连接你的知乎收藏夹，先告诉你哪篇值得读，再陪你逐段读到懂。

# 一、核心创作思路与目标用户

## 1.1 你是否有过这样的场景

深夜刷知乎，看到一篇好回答，写得确实明白。你想，这么好的内容，先码住，周末专门抽时间好好读一遍。于是点下收藏，心里挺踏实，感觉这篇的知识已经到手了。

然后就没有然后了。那个周末一直没来。几个月后整理收藏夹，两百多条收藏躺在那里，时间最近的停在上个月，最久的已经两年多，一篇都没有再打开过。**收藏从未停止，学习从未开始。**

偶尔下决心点开一篇，读了三段，撞上一个看不懂的概念，卡住，退出，顺手又收藏了一篇讲这个概念的。问题没有解决，收藏夹倒是更长了。

这件事断在三个环节：收藏太多，挑不出哪篇值得花时间；真去读，缺的背景没人补，断掉的推导接不上；读没读完、懂没懂，也没有人管。知识蒸馏站做的就是这三件事。

## 1.2 我们的思路：不做总结 AI，做精读仪器

面对读不进去，很多工具的答案是帮你总结，把一篇好文章压成三句话。但这样做和学习目标是矛盾的。Bastani 等人 2025 年发表在 PNAS 的实验发现，无约束地把答案递给学习者的那一组，撤走 AI 后成绩比从没用过 AI 的对照组还低 17%；而让学习者自己解释、自己推进的学习方式，Bisra 等人 2018 年的元分析给出的效应量是 0.55，短会话里效果更好。

所以知识蒸馏站的 AI 只站在辅助的位置上，**不替用户读**。它做三件事：筛选，量化一篇内容的阅读价值；补齐，解释你缺的背景，指出逻辑断点；检测，出题检验你是否真的读懂。而读和想通，始终由用户自己完成，节奏由你的"我懂了"推进。

## 1.3 目标用户

在校学生和毕业三年内的职场新人。他们有收藏习惯，有学习焦虑，时间碎片化，不缺内容，缺的是把内容变成自己东西的方法。

# 二、用户如何完成核心体验

产品的核心流程是一条线：先筛选，再发现，然后精读，读完留痕，全程有学习智能体可以对话。

## 2.1 筛选：把收藏夹变成可以排序的清单

用知乎账号登录后，收藏夹全量加载为内容卡片。每篇内容有三个独立计算的指标：

| 指标 | 回答的问题 | 依据 |
|---|---|---|
| 认可度 | 社区觉得它好吗 | 赞同、评论、收藏三个计数对数加权 |
| 信息量 | 它有干货吗 | 标题与摘要的长度、结构、引用密度 |
| 准确性 | 它可信吗 | 作者认证信息等公开信号 |

用户可以按任一单项或综合分排序，鼠标悬停能看到每一分的计算依据。

## 2.2 发现：收藏夹空着，也能开始

收藏夹没东西的用户不会被挡在门外。输入一个想搞懂的关键词，就能搜到知乎站内的相关内容，点开原文收藏或保存，直接进入学习。已经有收藏的用户，系统会根据收藏画像推荐同主题的内容作为补充。推荐只做发现，不做替换，收藏是用户自己的选择。

## 2.3 精读：逐段读到懂

点开一篇已保存全文的内容，进入精读会话。全文先由 AI 切成 600 字左右、按语义边界划分的段落，一次只读一段。界面分两栏，左栏是原文，右栏是这一段的解释。解释里会补上文章默认读者懂、新手却没有的背景；读解释时还有疑问，可以继续追问，一层一层往下。

选中任意文字可以生成解释，这种解释带实线下划线，只对当前账号可见。打字提问同样是私有的，用虚线标记，可以锚定一段选区或者当前段落。文章更新后，未改段落继续复用本人的解释树；改动或删除的段落在新版不显示旧解释。底部的"我懂了"是唯一的推进方式，读完一段是一段，"上一段"随时退回。AI 不生成全文摘要，读的主体始终是用户。

## 2.4 学习智能体：会提问，也会找答案

精读页里有一个学习智能体。它不是普通的聊天窗口，回答问题时会自己调用外部工具。问刚刚发生的事、问会随时间变化的知识，它会现场检索全网和知乎站内的资料，带着来源回答，而不是凭训练时的旧记忆硬答。术语对照、公式演算、结构梳理这些内置技能，也会按问题的需要启用。它知道你正在读哪一段、之前划选过什么、问过什么，回答能接上你此刻的问题。查了什么、引用了哪里，页面上都看得到。

## 2.5 沉淀：读完之后，学过留痕

读完不等于结束。自测会出 5 道题，考知识记忆还是概念辨析、用判断还是选择，由模型根据内容决定。答错时，它会针对你选的那个选项讲清楚错在哪，而不是把正确答案再说一遍。复习按你的作答情况重点讲薄弱的地方，跳过也算不懂。每篇读到第几段会自动保存，侧边栏随时可以回到上次的位置。

## 2.6 会员

三指标筛选、逐段精读、个人解释、自测复习，对所有用户开放。会员解锁的是学习智能体的进阶使用：更高的对话额度，更充分的联网搜索和技能调用，支撑论文季、求职季这种高强度的学习；学习报告、跨篇知识串联这些新功能，也会先向会员开放。

所有用户保有自己的解释和学习轨迹，会员支撑更高强度的算力，产品靠这个长期运转，不靠广告。

# 三、整体技术方案

```
浏览器：原生前端，无构建
   │
FastAPI 服务端：Python
   ├─ 知乎开放平台 API ── 登录 / 收藏数据 / 知乎搜索 / 全网搜索
   ├─ DeepSeek 大模型 ── 分段 / 解释 / 智能体问答 / 出题 / 复习
   └─ 云开发 PostgreSQL ── 全文 / 分段计划 / 解释树 / 埋点，持久化
```

三个工程决策值得说明。分段不让模型直接输出字符切点，因为实测会出现幻觉偏移，实际做法是模型只给语义分组，服务端精确计算字符位置，左栏展示的永远是原文本身，位置锚定才可靠。分段计划、题库和搜索结果按文章或版本共享，文字解释与追问按账号隔离，只在同一账号、同一段身份延续到未改段落的新版本。智能体的联网搜索和技能调用由服务端编排，模型决定要不要查、查什么，检索在服务端完成，来源带回给用户。

数据存在云端数据库，全文、个人解释树、学习进度重启不丢。初始解释、划选解释和追问都只有本人可见。

# 四、使用的知乎开放能力

| 能力 | 用途 |
|---|---|
| OAuth 登录与用户基础信息 | 账号连接与身份展示 |
| 用户数据 API：收藏夹列表与内容全量分页 | 产品数据底座，把收藏夹变成三指标清单 |
| 知乎搜索 | 发现层的关键词搜索与画像推荐，获取作者认证信息 |
| 全网搜索 | 学习智能体的外部工具，提问时现场检索资料、补足上下文 |
| 额度查询 | 用量透明化与预算管理 |

本产品不抓取、不搬运知乎内容。全文来自用户在知乎页面上主动触发的书签保存，所有内容卡片都会跳转知乎原文。

# 五、与知乎社区生态的契合点

产品里的每次点击最终都回到知乎原文：卡片跳原文，收藏发生在知乎，保存由用户在知乎页面上主动完成。知识蒸馏站是知乎内容的加深层，不是替代品。

个人解释直接长在对应的知乎内容上。同一段原文在后续版本未改时，本人的解释树继续可用；其他账号看不到这些解释。

搜索和推荐都指向知乎站内内容，用户会被带回知乎，发现更多优质创作者。收藏从存了就忘，变成有下文的行为。

分段、题库和搜索结果继续共享缓存，让开放平台接口的每一次调用产生更大的价值，用量透明可查。

# 六、对社区用户的实际价值

对读者，挑一篇的时间从翻收藏夹变成按分数排一下；读长文有了分段和控速，读完一篇不再靠意志力；读不懂的地方有解释、有智能体找资料、有自测检验，懂没懂不再凭感觉。自己的划选解释和提问会沉淀成个人学习轨迹，并在未改段落的新版本中继续使用。

对创作者，你的回答会被更多人真正读完，而不是一直躺在收藏夹里。
