## 一、会话目标

**让用户把收藏的这一篇真正读进去。**

用户收藏了大量回答却没再打开过。会话把这个动作变成一个可完成、有节奏的过程：逐段精读，每段先给一层解释；读不懂的地方自己划出来追问；这段过了，进下一段。

**产品不做什么**：不替用户读、不生成摘要、不做全文总结。产品提供的是**分段 / 解释 / 追问**三层支撑，读的主体始终是用户。

> 更强的目标形态——「会话结束后，用户在没有 AI 辅助的情况下能自己讲出核心论证」——记录为拓展项 E1。

## 二、会话结构

### 2.1 分段

会话开始时，AI 把全文划分为若干**适合一次理解**的部分，同时产出一句**全文主旨**（供后续每段解释当上下文）。

划分的硬约束：

| 约束 | 内容 |
|---|---|
| **只定切点，不改文字** | 返回值是字符位置数组，不是重写后的文本。左栏展示的必须是原文本身 |
| **无损** | 各段拼接等于原文，不删减、不改写、不乱序 |
| **有序** | 切点严格递增 |
| **覆盖全文** | 不漏掉任何一段文字 |
| **语义边界优先** | 章节 / 自然段分界优先 |
| **长度上限** | 单段约不超过 1200 字 |

**依据**：Mayer 的**分段原则**（segmenting principle）——复杂内容拆成学习者可控节奏的小段，比连续呈现更利于学习，因为降低了同时处理的认知负荷。

### 2.2 界面

| 位置 | 内容 |
|---|---|
| 左栏 | 当前段的**原文**，可上下滚动，但**限于本段之内** |
| 右栏 | 当前段的**初始解释**（第 2 层），固定不变 |
| 底部 | 常驻对话栏：输入框 + **提问**（主操作）+ **我懂了** / **上一段**（导航） |

**沉浸优先**：不提供「去知乎看原文」的出口，不做段列表跳转，不显示标注计数。用户留在界面内，一次只看一段。

### 2.3 层级模型

| 层 | 内容 | 可变性 | 可见性 |
|---|---|---|---|
| 1 | 原文（当前段） | 不可改 | 所有人 |
| 2 | 初始解释（每段一个） | **固定不变** | 所有人 |
| 3+ | 选区解释 / 提问回答 | 可增可删 | 由锚点决定 |

第 3 层起以标签页打开，**可嵌套**——在某一层里再次选中，就生出它的子层。

**布局递归**：每一层的结构相同——左边是父文本（含高亮），右边是这一层的解释。用户只看得到自己的父节点，逐级可上溯。整个界面只有一个布局组件。

### 2.4 推进与回溯

**「我懂了」是唯一的推进方式**（滚动限制在段内，跨不过去）。

- 在**第 2 层**按下 → 本段结束，进入下一段
- 在**第 3 层及以下**按下 → 关闭当前层，回到上一层

「我懂了」不改动任何状态，只记一条埋点。

**「上一段」提供最小幅度的回溯**——退回上一段，可连按直到第一段（在第一段时该按钮不可用）。

**只保留这一个按钮，不做段列表、不做跳转。** 理由：破坏沉浸的是菜单和列表，不是后退一步；而「读到第 7 段发现前一段没接上，需要回去看一眼」是必然会出现的理解需求。

**回溯不恢复任何状态。** 第 2 层固定不变、选区标记永久有效，所以退回上一段看到的就是它本来的样子——只是把游标减一。

## 三、两种锚点

| | 选区锚点 | 提问锚点 |
|---|---|---|
| 锚定对象 | 文本区间 | 段落 / 当前层 |
| 占用文字 | **占**，不重叠 | 不占 |
| 可见性 | **全局共享** | **仅自己** |
| 持久性 | 持久 | 持久 |

**节点的可见性由锚点决定**：锚在共享文本上则共享，锚在私有内容上则私有（在私有回答里划选，产生的仍是私有节点）。

### 3.1 选区规则

**连续、不重叠、有序、不跨越。**

- 一个选区是一个**连续区间**，不能多段、不能分段选
- 提交前可自由重选或取消（草稿态，松手不等于提交）
- 同一段内两两不相交，按位置有序
- 拖动跨过已有标记时**在边界截断**——已有标记把可选区域切开，跨不过去
- **提交后永久固定，删除才释放**

> 不变式：**一个段落里的所有选区，把该段文字切成若干互不重叠的连续片段。**

### 3.2 统一提问栏

一个按钮管两种情况，靠「有没有输入」判别：

| 选中文本 | 输入内容 | 结果 |
|---|---|---|
| 有 | 无 | **共享选区解释**——占文字区间、全站可见、进缓存 |
| 有 | 有 | **私有提问**——锚定该选区，不占文字 |
| 无 | 有 | **私有提问**——锚定当前段落 / 当前层 |
| 无 | 无 | 按钮禁用 |

**规则：纯选中 = 给集体加一条解释；打了字 = 自己的问题。**

这样两种语义自动分开，一个按钮，没有模式切换。私有提问不注册文字区间，因此不参与「不重叠」规则，不会占用或阻塞任何公共资源。

## 四、视觉

| 状态 | 视觉 | 生命周期 |
|---|---|---|
| 草稿选区 | 明显的选中高亮 | 临时，提交或取消即消失 |
| 共享选区 | **实线**下划线 | 永久 |
| 私有提问锚点 | **虚线**下划线（仅自己可见） | 永久 |

三类用不同的视觉通道，可以叠加——同一段文字既是共享选区、又被自己问过时，实线 + 虚线并存，不打架。

**按下提问钮后标记样式变化，就是提交成功的反馈**，不需要额外提示。

**原则：凡锚在文字上的东西，都在文字上可见。** 不用计数器、不用角标、不用入口文字，右栏保持安静。

### 4.1 公式的渲染与标记（9/14 补充）

原文里的数学公式是 LaTeX 源码（知乎页面经书签送入后不带分隔符），对读者不可读，**必须在左栏就地编译**（KaTeX，本地化，见企划书 T10）。覆盖范围是精读页**所有可见文本**：左栏原文、右栏解释与回答、回答卡片里的问题、顶部文章标题、侧边栏学习记录标题。

**识别口径**（9/14 扩充）。原文没有分隔符，所以按两类线索认公式：① 带 LaTeX 命令（`\frac`、`\text`、`\alpha`）；② 带短上下标的表达式（`XW_Q`、`K^T`、`head_1`、`(G_1)`）。实现是「数学原子 + 连接符合并」：两个原子之间只有连接符和单字母变量才并成一条，**中文一律截断**（公式不会把中文句子卷进来），下标超过两位的标识符（`file_name`、`snake_case`）不算公式。这样中文句子里的裸公式（`其中 Q, K, V = XW_Q 分别表示…`）也能编译，同时不误伤代码式命名。

这带来一个约束：

**偏移不变式不得破坏。** 左栏的字符下标是划选、标记锚点、层级嵌套、删除子树的唯一坐标（见第三节）。公式编译后 DOM 文本长度与原文不再相等，因此：

- 每个公式元素把它的原文区间记在 DOM 上，换算偏移时**整体按原子处理**（光标落在公式内 → 吸附到公式的起点或终点）；
- 标记与公式相交时向外扩到整条公式——**公式不能被划开一半**；
- 编译失败的片段退回原文显示，不显示报错框（宁可不渲染，也不给读者一屏红色公式）。

标记在公式上的视觉随之分两种：**行内公式**沿用下划线（下划线贴着公式）；**独立成行的公式**在 display 模式下是块级，下划线会横贯整行、读起来像分隔线，因此改用整行浅底纹表达「这一块被标了」。

**面向模型的约束**：解释与回答里的公式要求用 `$…$`（行内）或 `$$…$$`（独立成行）包裹输出（`server/core/ai.py`），右栏据此渲染；裸 LaTeX 只作为原文的兼容路径存在。

## 五、两个出口

| | 我懂了 | 删除解释 |
|---|---|---|
| 关闭窗口 | 是 | 是 |
| 标记 | **不动** | **抹掉**，文字释放 |
| 解释内容 | 保留、缓存命中 | **清除**（含全部子层） |
| 语义 | 收起来 | 不要了 |

**删除必须人人可用。** 因为选区不重叠、共享且永久——如果删除受限，一个人划满全文就永久锁死了所有人的提问空间。删除开放，坏标记才能被清理，而且内容会**自愈**：下一个人点开同一处会自动重新生成。

**删除的连锁**：标记消失 + 解释清除 + **整棵子树一起走**（子选区长在被删节点的文本里，文本没了就没有依附对象）。兄弟节点不受影响。

## 六、数据与存储

**服务器数据只进数据库**（不使用 SQLite，不使用文件落盘）。

- 数据库负责持久，内存缓存继续负责加速
- 具体选型与表结构待定
- **数据库是部署的前置项**——没连通服务起不来

> ⚠️ T1 记录了「依赖控制在最小集：fastapi / uvicorn / httpx」。接入数据库客户端是对该决策的突破，动的时候需在企划书登记。
> 提示：T5 定的 CloudBase 自带云数据库，接平台自己的可少一个外部依赖和一个网络故障点。

## 七、状态模型

| 层 | 内容 | 生命周期 |
|---|---|---|
| **全局共享** | 段落划分 + 初始解释 + 选区注解树 | 持久 |
| **用户私有** | 打字提问及其追问链 | 持久 |
| **会话** | 当前段落游标 | 内存 |
| **埋点** | 事件流（open / understood / deleted） | 只追加 |

**埋点与呈现分离**：我懂了只写日志，界面不为它改变任何东西（无已读样式、无个人进度）。

三个可算出的指标：

- **热度** = 某选区被打开次数 → 读者自己标出的难点
- **删除率** = deleted / open → 解释质量，调 prompt 的靶子
- **接受率** = understood / open → 解释有没有效果

**额外收获**：用户的私有提问历史本身就是他的学习记录——在哪几段反复问、问了什么，比任何测验都具体，而且是他自愿留下的。

### 7.1 删除学习记录 = 重置这篇文章（9/14）

侧边栏的「学习记录」是 **open 埋点的派生视图**（每篇文章取最新一条，用来看"读到哪里"）。

**删除一条记录，同时把这篇文章重置为「未保存全文」**：收藏卡回到「🧪 去保存全文」，可以重新用书签保存一次。

**为什么必须连全文一起删**：卡片上的「✓ 已保存」由服务端 `/api/distilled` 驱动（判断依据是这篇的全文在不在库里），**前端改标记是假的**——全文还在的话刷新一下卡片就又亮了；而且不删全文时重新保存会被 ingest 的幂等逻辑挡回（返回 `existed`），存错的内容永远换不掉（这正是 9/14 想手工删库的那个需求）。

删除范围（一张表都不能漏）：

| 对象 | 内容 | 为什么 |
|---|---|---|
| `distilled` | 这篇的全文 | 卡片状态的依据；也是重新保存的前提 |
| `reading_articles` | 分段切点 + 全文主旨 | 切点是按这篇全文算的字符位置 |
| `reading_nodes` | 初始解释 / 共享选区解释 / 私有提问 | `pos_start/pos_end` 锚在全文上，全文没了就失去参照 |
| `reading_events`（仅本人） | 自己的学习记录埋点 | 删的就是这条记录；别人的埋点不动 |

⚠️ **两个必须知道的取舍**：

1. **全文是按内容键全局共享的**（为省额度：三指标/讲解/分段都按内容键复用，见第三节 T3）。所以删除影响的不只是自己——其他用户对这篇的分段、解释与标记会一起失效，下次打开会重新生成。单账号演示无感知，多人同时用时是真实的相互影响。
2. **不可恢复**：删掉后只能重新用书签保存一次全文。

前端行为：删的若是当前正在读的那篇 → 直接回起始页（全文已重置，会话无法继续）；收藏页删除后会重新拉 `/api/distilled` 并重绘卡片，徽章当场变回「去保存全文」。二次点击确认按钮的 tooltip 写明「删除这条学习记录，并把这篇重置为未保存全文」。

> 实现：`DELETE /api/reading/history?url=…` → `store.delete` + `reading_store.delete_plan_and_nodes` / `delete_user_events`；
> 记录折叠逻辑 `collapse_history` 是纯函数，有 pytest 覆盖。

### 7.2 原文配图：内联回原位 + 点图解释（9/14）

**配图内联**：图片按它在正文中的**字符位置**插回左栏原文，不再单独堆在下面。图片是**零长原子**——它在原文里不占字符，所以划选、标记锚点、层级嵌套用的偏移映射完全不受影响。

位置从哪来（书签抓取，`app.js:buildBookmarklet`）：抓取时先给每张候选图前插一个不可见标记（U+2063），`innerText` 会把标记放在图片真实位置上；读出文本后，把标记从文本和 DOM 里清掉。实测结论：**正文与改动前逐字一致**（去掉换行后完全相同），唯一差别是图片位置多出两个空行——正好把图夹在两段之间，成了它的块间距。

| 规则 | 说明 |
|---|---|
| 抓取上限 | 3 → 9 张（与 `/api/ingest` 上限一致） |
| 归属 | 按切点区间归属到**唯一一段**，不会在相邻两段重复；夹在段间空白的夹到段首/段尾 |
| 旧数据 | 早期保存的没有位置记录 → 退回下方「未定位配图」栏（图不丢；重新用书签保存一次即变内联） |

**点图解释**（点内联图或未定位缩略图，右栏显示）：

| 项 | 决定 |
|---|---|
| 模型 | `deepseek-flash`（DeepSeek 的视觉能力在这个模型上，见官方 Vision 指南）；文本仍走 `deepseek-chat` |
| 上下文 | 用抓取时记下的位置，服务端截取图片位置前后的原文（各约 400 字，向两侧对齐到换行边界）交给模型——**图片就插在这两段之间**，是真实上下文而不是猜；位置缺失时退回只依据标题与主旨 |
| 传图方式 | 服务端先抓图转 base64 data URL（知乎图床有防盗链；顺带卡住 ≤8MB） |
| 缓存 | 按图片 URL 全局缓存（同一张图只生成一次，省额度） |
| 立场 | 只说「这张图是什么、该看哪里、与上下文什么关系」，不复述正文、不替读者下结论；看不清就直说 |
| 安全 | 图片 URL **只收知乎图床**（`zhimg.com` / `zhihu.com` 及子域）。配图由服务端抓取，不限制域名的话 `/api/ingest`（无需登录）就能被用来探测内网地址（SSRF） |

> ⚠️ **需要手动建表**（CloudBase 控制台 SQL 编辑器执行一次）。未建表时点图返回 `DB_FAILED`，**内联显示不受影响**：
> ```sql
> create table if not exists image_explanations (
>   url text primary key,
>   content text not null,
>   at bigint not null
> );
> ```

## 八、基础实现 vs 拓展

### 8.1 基础实现（本次范围）

上述全部，另加两件：

1. **读完最后一段后的出口**——至少一个返回收藏夹的入口。否则最后一个「我懂了」按下就是死路
2. **按段生成**——进入某段时生成那段的解释，不预生成全文。首屏成本 = 1 次划分 + 1 次当前段解释

（「上一段」回溯已并入基础实现，见 2.4。）

### 8.2 拓展（记录，不在本次范围）

| 编号 | 内容 | 说明 |
|---|---|---|
| **E1** | **产出动作** | 底部输入栏占位提示改成「用一句话说说这段讲了什么」，用户打了就是产出，自动进私有记录。让用户从「读」变成「讲」，对准「离开 AI 能复述」的目标 |
| **E2** | **解释跑偏反馈** | 第 2 层加一个「这段解释不对」按钮，不改内容只记事件——调 prompt 的高价值信号 |
| **E3** | **读完统计与推荐** | 钻了几处、哪几段是重点、推荐下一篇 |
| **E4** | **段落级提问的入口** | 不选文本直接打字的提问没有可标位置，目前只能靠标签页保持打开；关掉则界面上找不到（内容仍在库里） |

## 九、与原有设计的关系

- 原 **F9（补共识）/ F10（拆逻辑）/ F11（补材料）/ F12（追问对话）作废**，由本设计的「初始解释 + 划选追问」承接
- **「补共识」的定位修正**：从「事后按需补」改为**初始解释的前置部分**——文章默认读者有、但新手没有的领域共识，在解释里先给。这是它的正确位置：不给，用户读不下去
- **「拆逻辑」的形态修正**：不是 AI 拆好给用户看，而是**用户自己拆、AI 指出断在哪里**。推导由用户完成
- **D1（学习方式）研究完成**，本设计即其结论

## 十、研究依据（供对外计划书引用）

| 设计选择 | 依据 |
|---|---|
| AI 分段、学习者控制节奏 | Mayer 分段原则（segmenting principle），降低同时处理的认知负荷 |
| 初始解释前置（对新手先给示范） | 认知负荷理论的工作示范效应；专长逆转效应（Kalyuga）——指导对低知识水平学习者有益。Kestin et al., *Scientific Reports* 2025（DOI 10.1038/s41598-025-97652-6）的 RCT 正是"给完整分步讲解"的设计，增益 0.63–1.3 SD |
| 推导由用户自己补 | 自我解释（self-explanation）：Bisra et al., *Educational Psychology Review* 2018 元分析 g=0.55，**时长 <30 分钟的会话 g=0.709**（短会话效果更好） |
| 追问只指出断点、不代劳 | Bastani et al., *PNAS* 2025（DOI 10.1073/pnas.2422633122）：无约束给答案的组，撤走 AI 后成绩比从未使用过 AI 的还低 17%；带保护设计的组无此负效应 |
| 「我懂了」作为推进节奏 | 分段原则中的学习者控速（learner-paced） |
| 共享标注、越用越全 | 知乎开放平台额度约束（每能力组 100 次/天）下的必然选择：解释只生成一次，成本随用户数递减 |
