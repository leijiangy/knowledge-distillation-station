## 二、核心设计原则（从上述资料提炼）

### frontend-design 的核心观点

**AI 生成设计的 5 大默认套路（要避免）**：
1. 暖米色背景（≈#F4F1EA）+ 高对比衬线 + 陶土色强调（≈#D97757）
2. 近黑背景 + 单一亮色（酸绿/朱红）强调
3. 报纸式排版（细线、零圆角、密集分栏）
4. SaaS 卡片套装（统一切割成一样圆角卡片 + 同一种柔和阴影）
5. 模板化装饰（全大写小标签、·分隔的 meta 串、等宽字体数据标签、无意义编号）

**工作方法**：先做设计计划（4-6 个命名色值 / 字体及角色 / 布局线框 / 设计原则）→ 对照brief审查"这是不是换成任何产品都成立的方案" → 通过后才实现。

**克制原则**：Spend your boldness in one place（把大胆只花在一处），其余保持安静；出门前摘掉一件配饰。

### swiftui-design-skill 的核心观点

**6 条设计哲学**：
1. 从上下文出发，不做"空白页设计"
2. 快速给假设、快速迭代（灰块占位 > 糟糕的 AI 生成素材）
3. 给 2-3 个方向而非单一答案
4. 占位符 > 劣质实现
5. System First：每个元素都必须挣得位置，留白是特性不是空虚
6. Anti-AI-Slop（禁则见下）

**Anti-AI-Slop 禁则（部分）**：
- ❌ 紫→蓝渐变背景
- ❌ **Emoji 当功能图标**
- ❌ 左 border 强调色的圆角卡片

### 排版原则（The Elements of Typographic Style 摘引）

- 行长 < 80 字符（中文约 35-40 字）
- 字体选择要有意为之，避免默认字体栈
- 字号层级清晰；衬线正文比无衬线需要更大行高

### 写作原则（frontend-design）

- 文字是设计内容不是装饰；每个文字元素只干一件事
- 从用户视角命名（用户管理的是"通知"，不是"webhook 配置"）
- 主动语态；按钮说"保存更改"而不是"提交"
- 失败/空状态是引导时刻，不是情绪表达
- 平实语气：简单动词、句子大小写、无填充词

## 四、对本项目的应用结论

1. **避免 5 大套路**——此前三版预览（A 墨与琥珀 / B 深色实验室 / C 蓝白）分别踩了套路 1、2、4
2. **emoji 不能当功能图标**——logo 的 🧪 需要替换为手绘 SVG 图形标
3. **boldness 集中一处**——当前方案（护眼纸 + 方格/横线）的 boldness 应集中在"纸张"这一处，其余元素保持克制
4. **每个元素挣得位置**——文案不能承诺不存在的交互（如"悬停可查"必须有对应 hover 行为）

## 五、本轮界面素材（2026-09-14）

- **插画**：[`reading-illustration.webp`](../server/static/reading-illustration.webp)，用于首页与精读完成页；内置 image_gen 生成，1385 × 1136，透明背景。
- **文件处理**：从生成的 PNG 无损转为 WebP，860,044 字节，体积减少约 36%；已核对所有可见像素与 alpha 通道一致。
- **配套图标**：沿用页面已有 SVG 描边方式，在现有 HTML 与卡片模板里补充书本、书签、保存和精读图标。
- **视觉范围**：保留原绿色纸张风格、1080px 主页面宽度和动态背景，统一字体、留白、边框、状态反馈；精读窄屏修正仅涉及布局规则。
