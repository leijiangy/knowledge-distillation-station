# 部署指南（CloudBase 云托管）

> 目标：把 `server/` 部署为公网可访问的 HTTPS 服务，完成 OAuth 回调配置与真实登录验收。
> 代码侧已就绪：`server/Dockerfile` + `.dockerignore` + `/api/health` 健康检查。
> 控制台界面可能随版本变化，以实际界面为准；本文只锁定**必须做对**的事项。

## 一、部署前检查清单

- [ ] GitHub 仓库最新提交已推送（CloudBase 从仓库构建）
- [ ] 仓库为公开（CloudBase 拉取方便）；应用在 `server/` 子目录（monorepo）
- [ ] 本地已跑通：`python -m pytest tests` 15 项通过、`start.bat` 本地页面正常
- [ ] 准备好凭证（下方环境变量清单，**不要**写进任何文件提交）

## 二、环境变量清单（云托管「环境变量」配置里逐条填入）

| 变量 | 值 | 说明 |
|---|---|---|
| `ZHIHU_OAUTH_APP_ID` | `441` | 公开配置 |
| `ZHIHU_OAUTH_APP_KEY` | （赛事页面分配，敏感） | 从本项目 `.env` 取 |
| `ZHIHU_ACCESS_SECRET` | （开放平台生成，敏感） | 从本项目 `.env` 取 |
| `ZHIHU_OAUTH_REDIRECT_URI` | `https://<部署后拿到的域名>/auth/callback` | **第一轮部署先留空**，拿到域名后再填并重新部署 |
| `DEEPSEEK_API_KEY` | 从本项目 `.env` 取（敏感） | 学习会话（分段 / 解释 / 回答）用 |
| `CLOUDBASE_ENV_ID` | 云开发**环境 ID** | 数据持久化用；⚠️ 控制台网址里的 ID 可能与实际不符，以控制台「环境」页显示的为准 |
| `CLOUDBASE_API_KEY` | **服务端** API Key（控制台 → 环境管理 → API Key 配置 → 服务端 API Key） | 数据持久化用；不要用客户端 Key |
| `CONTENT_GIT_DIR` | `/data/content.git` | 版本裸仓库；`/data`必须是腾讯云COS的持久挂载，不能是容器临时目录 |
| `BILLING_ENABLED` | `0` | 首次部署保持关闭；完成下文DDL/RPC、迁移和验收后才能独立改为`1` |
| `RECHARGE_ENABLED` | `0` | 充值仍待JM最终确认，默认关闭 |
| `RECHARGE_CREDITS_PER_CNY` | 留空 | 只供未来充值兑换使用，不参与AI扣量；未确认时不得编造默认值 |
| `RECHARGE_PLANS_JSON` | `[]` | 支付关闭期间不返回充值档位 |
| `MODEL_TOKENIZER_DIR` | 固定版本资源目录 | 必须与`deepseek-flash`完整消息模板上界算法一致 |
| `PORT` | `80` | 或平台自动注入，Dockerfile 已适配 |

> 数据持久化（T9/D9）前置：先在云开发控制台的 **SQL 编辑器**创建 7 张表——`distilled`（全文）、`reading_articles`（分段 + 主旨）、`reading_nodes`（解释 / 提问节点树）、`reading_events`（埋点）、`image_explanations`（配图解释）、`reading_quizzes`（自测题目 + 概括）、`reading_quiz_attempts`（自测作答记录）；字段以 `server/core/store.py` 与 `server/core/reading_store.py` 中的读写代码为准。
>
> 后两张（自测）的建表语句：
> ```sql
> create table if not exists reading_quizzes (
>   article_key text primary key,
>   summary     text not null,
>   questions   text not null,     -- JSON 数组：题目与答案
>   by_uid      text not null,
>   at          bigint not null
> );
> create table if not exists reading_quiz_attempts (
>   article_key text   not null,
>   uid         text   not null,

>   correct     boolean not null,
>   chosen      text,

> 未建表时自测接口返回 `DB_FAILED`，**不影响精读与提问**（同 `image_explanations` 的处理方式）。

⚠️ **绝对不要设置 `ALLOW_SELF_MODE`** —— 它只允许本地开发使用；公网设置它 = 任何访客无需登录即可读到项目账号的私密收藏（P0 安全红线）。

## 三、CloudBase 部署步骤

1. 登录[腾讯云云开发控制台](https://console.cloud.tencent.com/tcb)（需腾讯云账号，新用户有免费额度）
2. 创建环境（按量计费；记住环境 ID）
3. 进入「云托管」→ 新建服务：
   - **部署方式：代码仓库**（推荐，免本地 Docker；本机无 Docker 环境）
   - 授权 GitHub，选择仓库 `leijiangy/knowledge-distillation-station`
   - **构建目录/根目录设为 `server`**（monorepo 关键，勿选仓库根）
   - 构建方式：Dockerfile（路径 `server/Dockerfile`）
4. **端口设为 80**（与 Dockerfile 的 `EXPOSE 80` 一致）
5. 先把腾讯云COS以文件系统方式持久挂载到容器`/data`。COS endpoint 必须带协议，例如上海地域填写 `https://cos.ap-shanghai.myqcloud.com`；只填 `cos.ap-shanghai.myqcloud.com` 会使 `cosfs /mount.sh` 直接失败。再在「环境变量」里填入第二节清单（`ZHIHU_OAUTH_REDIRECT_URI` 先留空）
6. 部署，等待构建完成 → 访问 `https://<默认域名>/api/health`，应返回 `{"ok":true,"project":"知识蒸馏站"}`

## 四、配置 OAuth 回调（部署后立即做）

1. 在云托管控制台找到服务的**默认访问域名**（形如 `https://xxx-yyy.tcb.qcloud.la`，自带 HTTPS）
2. 本项目需要回调地址：`https://<该域名>/auth/callback`
3. 回到云托管「环境变量」，把 `ZHIHU_OAUTH_REDIRECT_URI` 填为上一步的地址，**重新部署**
4. 到**赛事活动页面**（项目详情）登记**完全一致**的回调地址（协议、域名、路径一字不差；不要求自定义域名，用平台默认域名即可——自购域名需备案，48 小时来不及）

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 构建失败：找不到 main.py | 构建根目录设错，应为 `server` |
| 部署失败：`option url has invalid format` / `cosfs 挂载失败` | 对象存储 endpoint 缺少协议头；改成 `https://cos.<地域>.myqcloud.com` 后重新部署 |
| 页面打开 502 / 超时 | 端口不对：容器应为 80；检查 `PORT` 环境变量 |
| 登录跳转后报「回调地址不一致」 | `ZHIHU_OAUTH_REDIRECT_URI` 与赛事页面登记值必须完全一致（含尾部斜杠、协议） |
| 登录后立刻过期 | `expires_in` 处理正常；检查服务器时间是否同步 |
| 额度耗尽（Code 30002） | 缓存已内置（1 天 TTL）；确认未绕过缓存频繁刷新 |

## 七、高级解释接入说明（2026-09-15）

高级解释使用官方 `deepseek-harness-sdk==0.1.5rc1`。Python wheel 自带对应 DSH 运行时；正常执行不需要系统 Node 或 pnpm。`server/dsh/reading.patch.yml` 在官方 sdk-minimal 上关闭命令执行，仅挂载官方网页服务、HTTP 读取插件与网页工具。轻量 `reading-policy.mjs` 通过公开 Cordis 钩子限制调用次数与预算，不修改 DSH 内核。

- 模型默认 `deepseek-flash`，配置项为 `DSH_MODEL`；复用服务端 `DEEPSEEK_API_KEY`。密钥不传给网页，不在前端设置。
- 高级解释走原有 quote → reserve → worker → settle 流程，`ai_operations.action=advanced`；生成节点仍为 `reading_nodes.kind=explain`。高级和普通解释必须按 action 分开缓存，指纹还包含完整上下文、模型和插件版本。
- 会员只信任 `get_billing_account(actor_uid)` 的 `membership_tier=premium` 和带时区且未到期的 `membership_expires_at`。报价、提交均校验；数据库预留事务也必须核验，不能由浏览器字段授予会员。会员账号由管理员指定，本文不提供自动开通支付。
- 整次最多预留 120,000 Token（输入上限 100,000 + 输出上限 20,000），最多 5 次模型调用、4 次网页读取，180 秒超时。只按 DSH 保存的每次供应商响应 `usage.total_tokens` 汇总并以1 Token=1积分结算；cache、prompt、completion和reasoning子字段仅供一致性检查，不能在total之外加减。缺失/矛盾的total或未完整完成的输出不进入正常扣费。
- 每次请求使用独立临时 DSH 目录，结束后清理；SDK 子进程必须关闭，服务端取消和超时都回收执行。不要把工作目录隔离误认为可任意运行命令的沙箱。
- 网页读取支持公开 HTML、文本、GitHub README/源码。官方 HTTP 插件不解析 PDF；arXiv 优先尝试 HTML，只有摘要可读时解释应明确注明。登录墙、反爬和不可访问链接不能宣称已读全文。
- DSH 结果保留在现有解释区，链接可点击；手机端同样可用。生成时切换段落不会把旧结果覆盖到新段。

上线前置：现有账务迁移须完成 `advanced` action、会员状态、额度预留及结算的原子实现，按已确认规则提供普通账号每周期50,000 Token、会员每周期500,000 Token与Asia/Shanghai 04:00周期。未完成数据库迁移与实库验收前保持 `BILLING_ENABLED=0`。本轮 SDK 与网页测试使用本地模拟模型，没有调用付费模型，也没有修改生产数据库。

官方接口参考：[Python SDK](https://deepseek-harness.github.io/deepseek-harness/guide/python-sdk)、[网页插件](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/web)、[工具扩展机制](https://deepseek-harness.github.io/deepseek-harness/en/reference/cookbook/adding-a-tool)。

## 八、备用方案

- 云托管不可用时：任何支持 **Docker 或 Python 常驻进程**的平台均可（Zeabur / Sealos / 轻量服务器）。部署同一镜像，回调地址按新域名同步更新（赛事页面 + 环境变量两处）。
- 临时联调（可选）：内网穿透工具（cpolar 等）把本地 4173 映射为公网 HTTPS，可提前验证登录流程；但**回调地址以最终部署域名为准**，避免反复改登记值。

## 九、COS 挂载与版本仓库验收

本项目不使用付费 CFS。部署前在腾讯云侧把专用、非公开的 COS 存储以文件系统方式挂载到容器的 `/data`，应用固定使用 `CONTENT_GIT_DIR=/data/content.git`。挂载身份只授予该存储前缀所需的读、写、列举和删除权限；不得把 COS 密钥写入镜像、Git 仓库或前端。

部署顺序固定：

1. 先完成 COS 持久挂载，再启动应用；`/data` 不得映射到容器临时层。
2. 应用首次启动可在 `/data/content.git` 初始化裸 Git 仓库，并设置 `core.fsync=all`、`core.fsyncMethod=fsync`、`gc.auto=0`。
3. 启动自检必须通过 Git blob 写入/读回，以及 ref 加锁写入、读取、删除。任何一步失败，当前实例立即禁用版本写入并返回 `VERSION_STORAGE_UNAVAILABLE`；数据库中的当前内容投影仍可只读。
4. 重启或滚动发布后，从新实例读取部署前的同一 commit 和文章 ref。若读取不到，不得开启导入或版本更新。
5. COS 裸仓库和 PostgreSQL 必须成对备份、成对恢复；仅恢复其中一侧不能宣布恢复成功。

上线验收至少保存以下结果：挂载点、仓库绝对路径、自检时间、探测对象读回一致、探测 ref 已删除、重启前后 commit 一致，以及一次“Git 已保存但数据库发布失败”的恢复演练。不要用应用源码仓库代替内容仓库，也不要在挂载失败时自动退回 `/tmp` 或工作目录。

## 十、PostgreSQL 目标 DDL 与 RPC 合同

可执行迁移统一维护在 [`server/migrations/20260915_billing_rpc.sql`](../server/migrations/20260915_billing_rpc.sql)。它覆盖计费、内容版本更新和私有解释节点 RPC，并在旧版本字段尚未完成真实 Git 回填、旧主键不受支持时整段回滚。不要把本节示例 SQL 和迁移文件重复执行；以迁移文件为执行入口，本节用于说明前置条件、锁序和验收口径。

以下内容是目标合同，不由应用启动自动执行。先从真实环境导出 schema、索引、约束、函数和权限，并在备份副本或隔离验收库演练。已有的七张业务表可能与早期字段不同，因此先执行“可追加结构”，完成 Git 基线和数据回填，再执行“收紧约束”；不要把两段合并为一次盲目生产迁移。

计费口径固定为：文字模型 `deepseek-flash`；唯一实际扣量来源为供应商响应 `usage.total_tokens`；`1 Token = 1 积分 = 1,000,000 微积分`。普通账号每个周期50,000 Token，高级会员500,000 Token；周期键按 `Asia/Shanghai` 时间减4小时后取日期。高级版19.9元/月，当前购买与充值均关闭。

### 10.3 RPC 名称、参数和事务边界

Python 适配层固定调用以下 PostgREST RPC；数据库函数名和参数名必须逐字一致：

| RPC | 必需参数 | 单事务职责 |
|---|---|---|
| `get_billing_account` | `actor_uid` | 返回有效会员、当前周期行和钱包；无行时幂等建立零用量/零余额 |
| `create_ai_quote` | `actor_uid,p_operation_id,p_idempotency_key,p_request_hash,p_intent,p_messages,p_billing_policy,p_quoted_at,p_quote_expires_at,p_budget_valid_until,p_quoted_input_token_upper_bound,p_quoted_microcredits` | 校验固定模型/规则，推导quoted total，写quoted操作；同键同请求重放 |
| `reserve_ai_operation` | `actor_uid,p_operation_id` | 固化原`quota_period`与会员档位，先冻结周期Token，超额才冻结钱包微积分 |
| `claim_ai_operation` | `p_executor_token` | 用`FOR UPDATE SKIP LOCKED`领取一项reserved操作并写执行租约 |
| `record_ai_result` | `p_operation_id,p_executor_token,p_result_json,p_result_hash` | 只保存完整模型响应与真实usage，不扣量 |
| `finalize_ai_operation` | `p_operation_id` | 从已保存响应读取`usage.total_tokens`，在原周期结算、释放余量并创建结果节点 |
| `waive_ai_operation` | `p_operation_id,p_reason` | 失败、超时或契约不符时释放两类冻结，终态幂等 |
| `begin_content_update` | 以`server/core/store.py`当前调用为准 | 创建幂等内容更新任务并校验expected commit |
| `claim_content_update`、`save_content_candidate`、`mark_content_git_saved`、`publish_content_update`、`fail_content_update` | 以`server/core/store.py`当前调用为准 | 按queued→building→git_saved→published推进；DB发布使用CAS |

所有账务写RPC必须遵守同一锁序：有效会员权益 → `daily_token_quotas(uid,quota_period)` → `credit_wallets(uid)` → 段事务锁 → `ai_operations(id)` → 结果节点。预留公式为：

~~~text
U  = quoted_total_tokens
Rd = min(U, limit_tokens - used_tokens - reserved_tokens)
Rw = (U - Rd) * 1,000,000
~~~

结算只读取已持久化的 `usage.total_tokens=T`：

~~~text
Dd = min(T, reserved_daily_tokens)
Dw = (T - Dd) * 1,000,000
~~~

同一 finalize 事务必须完成：校验 `deepseek-flash`、校验 `T<=U`、更新原周期行、更新钱包、追加唯一流水、创建私有结果节点、写操作终态。跨北京时间04:00也只能结算操作行已固化的原周期。应用结果缓存命中不调用模型，两类消耗均为0；供应商prompt cache命中仍包含在真实 `usage.total_tokens` 中，不能另算也不能减免。

任何缺失/非法total、模型不匹配、total超预留或整数溢出，都必须在同一事务释放两类冻结、记录 `BILLING_CONTRACT_MISMATCH` 并关闭新生成；不能用字符数估算补账。所有reserve/settle/release流水使用唯一event key，重放不得重复改变额度或钱包。服务端service role是唯一写入口；匿名和普通JWT不得直接读写私人节点、操作、钱包和流水。

上线前用下列查询核对固定配置；必须返回一行且所有布尔表达式为true：

~~~sql
select
  billing_rule = 'total_tokens_1_to_1' as rule_ok,
  text_model = 'deepseek-flash' as model_ok,
~~~
