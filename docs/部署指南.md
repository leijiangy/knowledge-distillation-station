# 部署指南（CloudBase 云托管）

> 目标：把 `server/` 部署为公网可访问的 HTTPS 服务，完成 OAuth 回调配置与真实登录验收。
> 代码侧已就绪：`server/Dockerfile` + `.dockerignore` + `/api/health` 健康检查。
> 控制台界面可能随版本变化，以实际界面为准；本文只锁定**必须做对**的事项。

## 一、部署前检查清单

- [ ] GitHub 仓库最新提交已推送（CloudBase 从仓库构建）
- [ ] 仓库为公开（CloudBase 拉取方便）；应用在 `server/` 子目录（monorepo）
- [ ] 本地已跑通：`python -m pytest tests` 15 项通过、`start.bat` 本地页面正常
- [ ] 准备好凭证（下方环境变量清单，**不要**写进任何文件提交）

## 二、环境变量清单（云托管「环境变量」配置里逐条填入）

| 变量 | 值 | 说明 |
|---|---|---|
| `ZHIHU_OAUTH_APP_ID` | `441` | 公开配置 |
| `ZHIHU_OAUTH_APP_KEY` | （赛事页面分配，敏感） | 从本项目 `.env` 取 |
| `ZHIHU_ACCESS_SECRET` | （开放平台生成，敏感） | 从本项目 `.env` 取 |
| `ZHIHU_OAUTH_REDIRECT_URI` | `https://<部署后拿到的域名>/auth/callback` | **第一轮部署先留空**，拿到域名后再填并重新部署 |
| `DEEPSEEK_API_KEY` | 从本项目 `.env` 取（敏感） | 学习会话（分段 / 解释 / 回答）用 |
| `CLOUDBASE_ENV_ID` | 云开发**环境 ID** | 数据持久化用；⚠️ 控制台网址里的 ID 可能与实际不符，以控制台「环境」页显示的为准 |
| `CLOUDBASE_API_KEY` | **服务端** API Key（控制台 → 环境管理 → API Key 配置 → 服务端 API Key） | 数据持久化用；不要用客户端 Key |
| `PORT` | `80` | 或平台自动注入，Dockerfile 已适配 |

> 数据持久化（T9/D9）前置：先在云开发控制台的 **SQL 编辑器**创建 7 张表——`distilled`（全文）、`reading_articles`（分段 + 主旨）、`reading_nodes`（解释 / 提问节点树）、`reading_events`（埋点）、`image_explanations`（配图解释）、`reading_quizzes`（自测题目 + 概括）、`reading_quiz_attempts`（自测作答记录）；字段以 `server/core/store.py` 与 `server/core/reading_store.py` 中的读写代码为准。
>
> 后两张（自测）的建表语句：
> ```sql
> create table if not exists reading_quizzes (
>   article_key text primary key,
>   summary     text not null,
>   questions   text not null,     -- JSON 数组：题目与答案
>   by_uid      text not null,
>   at          bigint not null
> );
> create table if not exists reading_quiz_attempts (
>   article_key text   not null,
>   uid         text   not null,
>   q_index     int    not null,
>   correct     boolean not null,
>   chosen      text,
>   at          bigint not null
> );
> ```
> 未建表时自测接口返回 `DB_FAILED`，**不影响精读与提问**（同 `image_explanations` 的处理方式）。

⚠️ **绝对不要设置 `ALLOW_SELF_MODE`** —— 它只允许本地开发使用；公网设置它 = 任何访客无需登录即可读到项目账号的私密收藏（P0 安全红线）。

## 三、CloudBase 部署步骤

1. 登录[腾讯云云开发控制台](https://console.cloud.tencent.com/tcb)（需腾讯云账号，新用户有免费额度）
2. 创建环境（按量计费；记住环境 ID）
3. 进入「云托管」→ 新建服务：
   - **部署方式：代码仓库**（推荐，免本地 Docker；本机无 Docker 环境）
   - 授权 GitHub，选择仓库 `leijiangy/knowledge-distillation-station`
   - **构建目录/根目录设为 `server`**（monorepo 关键，勿选仓库根）
   - 构建方式：Dockerfile（路径 `server/Dockerfile`）
4. **端口设为 80**（与 Dockerfile 的 `EXPOSE 80` 一致）
5. 在「环境变量」里填入第二节清单（`ZHIHU_OAUTH_REDIRECT_URI` 先留空）
6. 部署，等待构建完成 → 访问 `https://<默认域名>/api/health`，应返回 `{"ok":true,"project":"知识蒸馏站"}`

## 四、配置 OAuth 回调（部署后立即做）

1. 在云托管控制台找到服务的**默认访问域名**（形如 `https://xxx-yyy.tcb.qcloud.la`，自带 HTTPS）
2. 本项目需要回调地址：`https://<该域名>/auth/callback`
3. 回到云托管「环境变量」，把 `ZHIHU_OAUTH_REDIRECT_URI` 填为上一步的地址，**重新部署**
4. 到**赛事活动页面**（项目详情）登记**完全一致**的回调地址（协议、域名、路径一字不差；不要求自定义域名，用平台默认域名即可——自购域名需备案，48 小时来不及）

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 构建失败：找不到 main.py | 构建根目录设错，应为 `server` |
| 页面打开 502 / 超时 | 端口不对：容器应为 80；检查 `PORT` 环境变量 |
| 登录跳转后报「回调地址不一致」 | `ZHIHU_OAUTH_REDIRECT_URI` 与赛事页面登记值必须完全一致（含尾部斜杠、协议） |
| 登录后立刻过期 | `expires_in` 处理正常；检查服务器时间是否同步 |
| 额度耗尽（Code 30002） | 缓存已内置（1 天 TTL）；确认未绕过缓存频繁刷新 |

## 七、备用方案

- 云托管不可用时：任何支持 **Docker 或 Python 常驻进程**的平台均可（Zeabur / Sealos / 轻量服务器）。部署同一镜像，回调地址按新域名同步更新（赛事页面 + 环境变量两处）。
- 临时联调（可选）：内网穿透工具（cpolar 等）把本地 4173 映射为公网 HTTPS，可提前验证登录流程；但**回调地址以最终部署域名为准**，避免反复改登记值。
