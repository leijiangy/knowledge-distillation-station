## 二、目标用户与痛点

**用户**：在校学生与毕业三年内的职场新人——有收藏习惯、有学习焦虑、时间碎片化。

**痛点**（两层）：
1. 收藏 ≠ 学会：收藏夹是知识坟场，收藏那刻以为会回看，实际再没打开；面对一堆标题不知道哪篇值得花时间；
2. 挑出一篇读，又卡在两处：**不了解的领域**（文章默认的领域共识，新手没有）、**跳跃的逻辑**（作者省略的推导，读者中间掉队）。

**为什么现有方案不够**：原生收藏夹只有列表；通用 AI 问答不接个人收藏、学完不沉淀；学习类 App 的内容不是用户真正想学的那篇。

## 三、产品定义

### 三层能力（递进，含用户旅程细节）

**第一层 · 看见**
1. 用户用知乎账号登录（OAuth）；
2. 系统读取收藏夹（favlists → favlist_contents 全量分页），带进度反馈；
3. 每条收藏展示：标题 + 三指标条 + 综合「学习价值」分 + 收藏时间 + 作者；
4. 用户浏览、排序（综合分 / 收藏时间）、点「我一直没弄懂」标记；
5. 选出目标 → 进入学习会话。

**第二层 · 替换**（⏸️ 暂停，9/13，待学习方式研究后重启）
1. 对选中内容用知乎全站搜索找同类；
2. 按三指标对比，推荐更高分 / 更好懂的替代或补充内容；
3. 用户可换更好懂的那篇开始学。

**第三层 · 学会**（⏸️ 暂停，9/13，待学习方式文献研究后重新设计；原设想如下）
1. **补共识**：生成「读这篇前你该知道的背景」，只讲领域共识，不重复原文；
2. **拆逻辑**：把推导链拆成步骤，标出跳跃点（作者省略了什么、为什么能省略）；
3. **补材料**：扫描文中论文 / GitHub 链接，解释「哪部分对应文章的哪个结论」。

### 三指标（口径定死，不得漂移）

| 指标 | 数据来源 | v1 口径 |
|---|---|---|
| 认可度 | 接口三计数（赞/评/藏） | 对数缩放加权，收藏权重最高 |
| 信息量 | Title/Summary | 长度、结构、引用密度、术语密度启发式 |
| 准确性 | 认证标 + 直答交叉 | v1 认证标分级；v2 直答抽查一致性 |

## 五、技术选型（逐项讨论）

> 每项列出：候选方案、倾向及理由、状态。由团队逐项确认。

| # | 选型项 | 候选 | 倾向与理由 | 状态 |
|---|---|---|---|---|
| T1 | 后端框架 | FastAPI / Flask / Django | **FastAPI + uvicorn**（团队熟 Python；异步原生支持、自动 API 文档、流式响应成熟）。依赖控制在最小集：fastapi / uvicorn / httpx | ✅ 已确认（9/13，随 D5） |
| T2 | 前端 | 原生 HTML/CSS/JS / React / Vue | **原生 HTML/CSS/JS**（9/13 团队授权由开发决定：无构建步骤、部署即用；交互复杂度低，框架是负收益） | ✅ 已确认（9/13） |
| T3 | 数据缓存 | 进程内存 dict / Redis / SQLite | **内存 dict + TTL**（两级：内容键全站共享 + 用户键私有；单实例部署；`node:sqlite`→Python 用 `sqlite3` 标准库可选持久化）。**跨用户共享缓存已确认采用**：三指标/讲解/搜索按内容键共享，收藏列表按用户键隔离 | ✅ 已确认（9/13） |
| T4 | AI 能力来源 | — | **DeepSeek（国内直连）**：OpenAI 兼容接口，密钥 `DEEPSEEK_API_KEY` 进 .env 与部署平台 Secret。模型档位与流式策略见 T8 | ✅ 已确认（9/13） |
| T5 | 部署平台 | — | **CloudBase（腾讯云开发，9/13 确认）**。部署要点：①使用**云托管（常驻容器）**而非云函数——内存缓存依赖常驻进程 ②默认 HTTPS 域名作 OAuth 回调（自购域名需备案，来不及）③App Key / Access Secret / DeepSeek Key 用平台环境变量注入 ④需要腾讯云账号（团队已有） | ✅ 已确认（9/13） |
| T6 | 样式方案 | 手写 CSS / Tailwind CDN / 组件库 | **手写 CSS**（随 T2 原生方案：无构建；设计感靠配色与卡片打磨） | ✅ 已确认（9/13） |
| T7 | 测试 | pytest / unittest / 不写 | **pytest**（三指标等纯函数必须有测试；接口层手工验收） | ⏳ |
| T8 | AI 调用策略 | 模型档位 / 流式开关 | **流式：启用**（团队已确认，边生成边显示，消除等待焦虑）。模型档位：`deepseek-chat` 起步，实测后决定是否对「拆逻辑」切 `deepseek-reasoner` | ⏳ 模型档位待实测 |
| T9 | 数据持久化 | 内存 / SQLite+CFS 挂载 / 云开发 SQL 数据库 | **SQLite（Python 标准库）+ 文件存储 CFS 挂载**（团队拍板 9/13，方案 B）：零依赖、免数据库服务；代价=需腾讯云 API 密钥授权挂载（已接受）。⚠️ 必须用 **CFS 文件存储**而非对象存储（SQLite 需要文件锁与随机写，对象存储不支持）。持久化对象（按优先级）：AI 蒸馏成果 > 学习进度标记 > 会话；随 B 组功能实现 | ✅ 已确认（9/13） |
| T10 | 公式渲染 | CDN 引 KaTeX / 本地化 KaTeX / MathJax | **本地化 KaTeX 0.18.7**（9/14）：原文里的 LaTeX 在精读界面对读者不可读，必须编译。选 KaTeX 是体积与速度优先；**资源入仓库（`server/static/vendor/katex`，仅 woff2 字体，约 600KB）而非 CDN**——演示环境与国内网络都不依赖外链。代价：新增前端第三方资源（不进 Python 依赖清单），需在识别与偏移映射上自己写一层（见 `server/static/math.js`） | ✅ 已确认（9/14） |

## 七、技术方案与额度纪律

```
浏览器 ──> server/main.py（FastAPI，Python）
              ├─ /api/oauth/*        登录、回调、会话（照官方协议实现）
              ├─ /api/collections    收藏全量拉取（favlists + favlist_contents 分页）
              ├─ /api/analyze        三指标计算（纯函数 + pytest）
              ├─ /api/session/*      学习会话（知乎搜索检索 + DeepSeek 生成）
              └─ 两级缓存（内容键共享 + 用户键私有，TTL）——额度硬约束下的必须项
```

**目录结构**（Python 版）：

```
server/                    # Python 应用（FastAPI）
├── main.py                # 入口 + 路由分发
├── core/
│   ├── config.py          # 环境变量（.env 加载）
│   ├── oauth.py           # OAuth 流程（授权跳转/回调/state 校验）
│   ├── sessions.py        # 会话管理（内存）
│   ├── zhihu.py           # 知乎 API 封装（收藏/搜索/额度，统一鉴权与错误）
│   ├── cache.py           # 两级缓存
│   ├── analyze.py         # 三指标（纯函数）
│   ├── deepseek.py        # DeepSeek 调用（含流式）
│   └── study.py           # 学习会话编排
├── static/                # 前端（原生 HTML/CSS/JS，无构建）
├── tests/                 # pytest
├── requirements.txt       # fastapi / uvicorn / httpx
└── .env                   # 凭证（gitignore，绝不入库）
```

`app/`（官方 Node 脚手架）保留为 OAuth 协议的参考实现，Python 版验证通过后归档。

**知乎开放能力清单**（企划/计划书对外用同一份）：

| 能力 | 用途 | 位置 |
|---|---|---|
| 用户数据 API（收藏夹列表 / 收藏夹内容 / 近期收藏） | 读取用户收藏，产品数据底座 | 第一层 |
| 知乎搜索 / 全网搜索 | 找同类内容、认证标（准确性）、**学习会话的检索上下文** | 第二层 / 学习会话 |
| OAuth 登录 + 授权用户基础信息 | 用户登录与身份展示 | 全局 |
| 额度查询 | 用量展示与预算管理 | 运维 |
| 知乎直答 | （备选）检索式问答兜底，暂不采用 | 备用 |

**学习会话的数据流**（D7 确定后）：知乎搜索检索背景资料 → 作为上下文喂给外部 LLM → LLM 按我们的 prompt 生成「补共识 + 拆逻辑」→ 服务端返回前端。检索走知乎、生成走外部模型，两边的优势都用上。

**额度纪律**：每能力组 100 次/天。开发期打本地样本调试，线上必须命中缓存；界面展示用量。

**凭证安全**：App ID 公开；App Key / Access Secret 只在 .env 与部署平台 Secret；前端、日志、截图、视频零出现。
