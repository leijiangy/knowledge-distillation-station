## 二、目标用户与痛点

**用户**：在校学生与毕业三年内的职场新人——有收藏习惯、有学习焦虑、时间碎片化。

**痛点**（两层）：
1. 收藏 ≠ 学会：收藏夹是知识坟场，收藏那刻以为会回看，实际再没打开；面对一堆标题不知道哪篇值得花时间；
2. 挑出一篇读，又卡在两处：**不了解的领域**（文章默认的领域共识，新手没有）、**跳跃的逻辑**（作者省略的推导，读者中间掉队）。

**为什么现有方案不够**：原生收藏夹只有列表；通用 AI 问答不接个人收藏、学完不沉淀；学习类 App 的内容不是用户真正想学的那篇。

## 三、产品定义

### 三层能力（★ = 已实现，9/13 交付版）

**第一层 · 看见 ★**
1. 用户用知乎账号登录（OAuth；本地可开本人模式预览，公网部署默认关闭）；
2. 系统读取收藏夹（favlists → favlist_contents 全量分页），带加载反馈与"上次加载时间"；
3. 每条收藏展示：标题 + 三指标**分开展示**（悬停可见计算依据）+ 雷达图 + 收藏时间 + 作者（含认证徽章）+ 正文配图（单图缩略 / 多图并排）；
4. 用户浏览、排序（收藏时间 / 综合分 / 任一单项指标）、分页；
5. 点卡片分流：**已保存全文 → 直接进入学习**；未保存 → 打开知乎原文，走书签保存（保存完成自动跳回并进入学习）。

**第二层 · 发现 ★（原「替换」演化为「智能推荐」，见变更登记）**
1. 以收藏画像为种子（综合分最高的几篇标题）去知乎搜索同主题公共内容，排除已收藏 / 已保存；
2. 推荐卡片与收藏卡片同构（三指标 + 雷达图），支持「换一批」；
3. 已保存的推荐内容可直接进入学习；未保存的先走书签保存。
> 明确不做「把原收藏替换成别的文章」——收藏是用户自己的选择，产品只做发现与补充。

**第三层 · 学会：逐段精读 ★（取代原「补共识 / 拆逻辑 / 补材料」设想）**
设计定稿见附录 A，实现要点：
1. **AI 分段**：全文切成约 600 字、语义边界优先的段落（模型只给语义分组，字符切点由后端精确计算）；段首尾空白自动清理；
2. **两栏递归模型**：左栏 = 当前层的父文本，右栏 = 它的解释或回答；问原文 → 回答覆盖解释，问解释 → 解释左移成为新的一层；
3. **划选生成共享解释**：任意文本上划选即生成（实线下划线标记、全站共享、命中缓存不重复生成）；解释文本上同样可划选；
4. **私有提问**：打字提问锚定选区或当前层，仅本人可见（虚线标记）；
5. **层级下钻**：点标记逐层深入；同层点击替换、超过 5 层折叠为省略框、只逐层退出；
6. **推进节奏**：底部「我懂了 →」前进、「← 上一段」最小回溯，段控件可展开段列表跳转；
7. **学习记录**：每篇读到第几段自动入库（由埋点派生），侧边栏下拉随时恢复，当前篇高亮；
8. **不替用户读**：解释只补背景与关键断点，推导留给用户自己完成（研究依据见附录 A）。

| T6 | 样式方案 | 手写 CSS / Tailwind CDN / 组件库 | **手写 CSS**（随 T2 原生方案：无构建；设计感靠配色与卡片打磨） | ✅ 已确认（9/13） |
| T7 | 测试 | pytest / unittest / 不写 | **pytest**：已落地 `test_analyze.py`（三指标）、`test_pagination.py`、`test_oauth_state.py`（另含 `test_history.py` / `test_image_url.py`）；接口层走人工验收 | ✅ 已实现（9/13） |

| T9 | 数据持久化 | 内存 / SQLite+CFS 挂载 / 云开发 SQL 数据库 | **改为 CloudBase PostgreSQL + REST API**（见 D9）：实测共享集群不支持直连，官方路径是 PostgREST 风格 REST；无需 CFS 挂载。已落地并通过"重启不丢"验证 | ✅ 已落地（9/13） |

## 七、技术方案与额度纪律

```
浏览器 ──> server/main.py（FastAPI，Python）
              ├─ /api/oauth/*        登录、回调、会话（照官方协议实现）
```

## 一、会话目标

**让用户把收藏的这一篇真正读进去。**

用户收藏了大量回答却没再打开过。会话把这个动作变成一个可完成、有节奏的过程：逐段精读，每段先给一层解释；读不懂的地方自己划出来追问；这段过了，进下一段。

**产品不做什么**：不替用户读、不生成摘要、不做全文总结。产品提供的是**分段 / 解释 / 追问**三层支撑，读的主体始终是用户。

> 更强的目标形态——「会话结束后，用户在没有 AI 辅助的情况下能自己讲出核心论证」——记录为拓展项 E1。

---

## 二、会话结构

### 2.1 分段

会话开始时，AI 把全文划分为若干**适合一次理解**的部分，同时产出一句**全文主旨**（供后续每段解释当上下文）。

划分的硬约束：

| 约束 | 内容 |
|---|---|
| **只定切点，不改文字** | 返回值是字符位置数组，不是重写后的文本。左栏展示的必须是原文本身 |
| **无损** | 各段拼接等于原文，不删减、不改写、不乱序 |
| **有序** | 切点严格递增 |
| **覆盖全文** | 不漏掉任何一段文字 |
| **语义边界优先** | 章节 / 自然段分界优先 |
| **长度上限** | 单段约不超过 1200 字 |

**依据**：Mayer 的**分段原则**（segmenting principle）——复杂内容拆成学习者可控节奏的小段，比连续呈现更利于学习，因为降低了同时处理的认知负荷。

### 2.2 界面

| 位置 | 内容 |
|---|---|
| 左栏 | 当前段的**原文**，可上下滚动，但**限于本段之内** |
| 右栏 | 当前段的**初始解释**（第 2 层），固定不变 |
| 底部 | 常驻对话栏：输入框 + **提问**（主操作）+ **我懂了** / **上一段**（导航） |

**沉浸优先**：不提供「去知乎看原文」的出口，不做段列表跳转，不显示标注计数。用户留在界面内，一次只看一段。

### 2.3 层级模型

| 层 | 内容 | 可变性 | 可见性 |
|---|---|---|---|
| 1 | 原文（当前段） | 不可改 | 所有人 |
| 2 | 初始解释（每段一个） | **固定不变** | 所有人 |
| 3+ | 选区解释 / 提问回答 | 可增可删 | 由锚点决定 |

第 3 层起以标签页打开，**可嵌套**——在某一层里再次选中，就生出它的子层。

**布局递归**：每一层的结构相同——左边是父文本（含高亮），右边是这一层的解释。用户只看得到自己的父节点，逐级可上溯。整个界面只有一个布局组件。

### 2.4 推进与回溯

**「我懂了」是唯一的推进方式**（滚动限制在段内，跨不过去）。

- 在**第 2 层**按下 → 本段结束，进入下一段
- 在**第 3 层及以下**按下 → 关闭当前层，回到上一层

「我懂了」不改动任何状态，只记一条埋点。

**「上一段」提供最小幅度的回溯**——退回上一段，可连按直到第一段（在第一段时该按钮不可用）。

**只保留这一个按钮，不做段列表、不做跳转。** 理由：破坏沉浸的是菜单和列表，不是后退一步；而「读到第 7 段发现前一段没接上，需要回去看一眼」是必然会出现的理解需求。

**回溯不恢复任何状态。** 第 2 层固定不变、选区标记永久有效，所以退回上一段看到的就是它本来的样子——只是把游标减一。

---

## 三、两种锚点

| | 选区锚点 | 提问锚点 |
|---|---|---|
| 锚定对象 | 文本区间 | 段落 / 当前层 |
| 占用文字 | **占**，不重叠 | 不占 |
| 可见性 | **全局共享** | **仅自己** |
| 持久性 | 持久 | 持久 |

**节点的可见性由锚点决定**：锚在共享文本上则共享，锚在私有内容上则私有（在私有回答里划选，产生的仍是私有节点）。

### 3.1 选区规则

**连续、不重叠、有序、不跨越。**

- 一个选区是一个**连续区间**，不能多段、不能分段选
- 提交前可自由重选或取消（草稿态，松手不等于提交）
- 同一段内两两不相交，按位置有序
- 拖动跨过已有标记时**在边界截断**——已有标记把可选区域切开，跨不过去
- **提交后永久固定，删除才释放**

> 不变式：**一个段落里的所有选区，把该段文字切成若干互不重叠的连续片段。**

### 3.2 统一提问栏

一个按钮管两种情况，靠「有没有输入」判别：

| 选中文本 | 输入内容 | 结果 |
|---|---|---|
| 有 | 无 | **共享选区解释**——占文字区间、全站可见、进缓存 |
| 有 | 有 | **私有提问**——锚定该选区，不占文字 |
| 无 | 有 | **私有提问**——锚定当前段落 / 当前层 |
| 无 | 无 | 按钮禁用 |

**规则：纯选中 = 给集体加一条解释；打了字 = 自己的问题。**

这样两种语义自动分开，一个按钮，没有模式切换。私有提问不注册文字区间，因此不参与「不重叠」规则，不会占用或阻塞任何公共资源。

## 四、视觉

| 状态 | 视觉 | 生命周期 |
|---|---|---|
| 草稿选区 | 明显的选中高亮 | 临时，提交或取消即消失 |
| 共享选区 | **实线**下划线 | 永久 |
| 私有提问锚点 | **虚线**下划线（仅自己可见） | 永久 |

三类用不同的视觉通道，可以叠加——同一段文字既是共享选区、又被自己问过时，实线 + 虚线并存，不打架。

**按下提问钮后标记样式变化，就是提交成功的反馈**，不需要额外提示。

**原则：凡锚在文字上的东西，都在文字上可见。** 不用计数器、不用角标、不用入口文字，右栏保持安静。

## 五、两个出口

| | 我懂了 | 删除解释 |
|---|---|---|
| 关闭窗口 | 是 | 是 |
| 标记 | **不动** | **抹掉**，文字释放 |
| 解释内容 | 保留、缓存命中 | **清除**（含全部子层） |
| 语义 | 收起来 | 不要了 |

**删除必须人人可用。** 因为选区不重叠、共享且永久——如果删除受限，一个人划满全文就永久锁死了所有人的提问空间。删除开放，坏标记才能被清理，而且内容会**自愈**：下一个人点开同一处会自动重新生成。

**删除的连锁**：标记消失 + 解释清除 + **整棵子树一起走**（子选区长在被删节点的文本里，文本没了就没有依附对象）。兄弟节点不受影响。

## 七、状态模型

|---|---|---|
| **全局共享** | 段落划分 + 初始解释 + 选区注解树 | 持久 |
| **用户私有** | 打字提问及其追问链 | 持久 |
| **会话** | 当前段落游标 | 内存 |
| **埋点** | 事件流（open / understood / deleted） | 只追加 |

**埋点与呈现分离**：我懂了只写日志，界面不为它改变任何东西（无已读样式、无个人进度）。

三个可算出的指标：

- **热度** = 某选区被打开次数 → 读者自己标出的难点
- **删除率** = deleted / open → 解释质量，调 prompt 的靶子
- **接受率** = understood / open → 解释有没有效果

**额外收获**：用户的私有提问历史本身就是他的学习记录——在哪几段反复问、问了什么，比任何测验都具体，而且是他自愿留下的。

## 八、基础实现 vs 拓展

### 8.1 基础实现（本次范围）

上述全部，另加两件：

1. **读完最后一段后的出口**——至少一个返回收藏夹的入口。否则最后一个「我懂了」按下就是死路
2. **按段生成**——进入某段时生成那段的解释，不预生成全文。首屏成本 = 1 次划分 + 1 次当前段解释

（「上一段」回溯已并入基础实现，见 2.4。）

### 8.2 拓展（记录，不在本次范围）

| 编号 | 内容 | 说明 |
|---|---|---|
| **E1** | **产出动作** | 底部输入栏占位提示改成「用一句话说说这段讲了什么」，用户打了就是产出，自动进私有记录。让用户从「读」变成「讲」，对准「离开 AI 能复述」的目标 |
| **E2** | **解释跑偏反馈** | 第 2 层加一个「这段解释不对」按钮，不改内容只记事件——调 prompt 的高价值信号 |
| **E3** | **读完统计与推荐** | 钻了几处、哪几段是重点、推荐下一篇 |
| **E4** | **段落级提问的入口** | 不选文本直接打字的提问没有可标位置，目前只能靠标签页保持打开；关掉则界面上找不到（内容仍在库里） |

## 九、与原有设计的关系

- 原 **F9（补共识）/ F10（拆逻辑）/ F11（补材料）/ F12（追问对话）作废**，由本设计的「初始解释 + 划选追问」承接
- **「补共识」的定位修正**：从「事后按需补」改为**初始解释的前置部分**——文章默认读者有、但新手没有的领域共识，在解释里先给。这是它的正确位置：不给，用户读不下去
- **「拆逻辑」的形态修正**：不是 AI 拆好给用户看，而是**用户自己拆、AI 指出断在哪里**。推导由用户完成
- **D1（学习方式）研究完成**，本设计即其结论

## 十、研究依据（供对外计划书引用）

| 设计选择 | 依据 |
|---|---|
| AI 分段、学习者控制节奏 | Mayer 分段原则（segmenting principle），降低同时处理的认知负荷 |
| 初始解释前置（对新手先给示范） | 认知负荷理论的工作示范效应；专长逆转效应（Kalyuga）——指导对低知识水平学习者有益。Kestin et al., *Scientific Reports* 2025（DOI 10.1038/s41598-025-97652-6）的 RCT 正是"给完整分步讲解"的设计，增益 0.63–1.3 SD |
| 推导由用户自己补 | 自我解释（self-explanation）：Bisra et al., *Educational Psychology Review* 2018 元分析 g=0.55，**时长 <30 分钟的会话 g=0.709**（短会话效果更好） |
| 追问只指出断点、不代劳 | Bastani et al., *PNAS* 2025（DOI 10.1073/pnas.2422633122）：无约束给答案的组，撤走 AI 后成绩比从未使用过 AI 的还低 17%；带保护设计的组无此负效应 |
| 「我懂了」作为推进节奏 | 分段原则中的学习者控速（learner-paced） |
| 共享标注、越用越全 | 知乎开放平台额度约束（每能力组 100 次/天）下的必然选择：解释只生成一次，成本随用户数递减 |
